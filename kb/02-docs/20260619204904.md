## Use-case

Docs in the store are intentionally tiny and single-responsibility. The reading consequence is that a reader constantly needs *a little more* than the doc in front of them — and forcing a full navigation (losing place, context, scroll) for each peek would make the atomic store painful to read.

So the viewer's stance is: **navigation should be rare**. The reader pulls in what they need through **four escalating tiers**, only the last of which actually moves them:

1. **Hover** — a tooltip showing the referenced doc's summary (and secondary id badge). The cheapest peek.
2. **Single-click** — open the referenced doc in the **side panel**, without leaving the current focus. (Formerly expand-in-place; in-place expansion disrupted reading flow.)
3. **Index composition** — inline a whole grouping: a signpost's guide plus its members, recombined as sections in the focus pane.
4. **Double-click** — **navigate / refocus** on the referenced doc. The only tier that changes where the reader is.

## Rationale

Atomic docs make peeks the common case and navigation the rare case. A side-panel peek preserves place and scroll in the focused doc while still giving a full body read — cheaper than navigation, less disruptive than expanding mid-prose.
