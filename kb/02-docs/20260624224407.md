When a doc is a duplicate, an empty stub, or a structurally redundant variant whose merge target already holds all its information, the correct action is deletion: `ldoc rm <ref>`. The command reports inbound edges and blocks deletion when **any inbound edge** exists unless `--force`. With `--force`, it strips **all inbound edges** from other docs, then deletes the target and reindexes automatically.

Deletion is the default retirement path. Deprecation (`status: deprecated` + `superseded_by` + `## Correction` section) is the exception, reserved for docs that recorded a genuine past decision or belief that was later overturned — cases where the historical record itself has value for future maintainers or for tracing why the system changed.

The failure mode to avoid: using deprecation as a default because it feels safer than deletion. A deprecated doc that holds no information the survivor does not already contain creates navigational noise without historical payoff. If removing the doc loses no information, delete it.

After any batch of deletions, run `ldoc validate`.
