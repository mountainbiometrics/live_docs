## Statement

Every doc except a pure **signpost** must carry its *why* — the rationale, constraint, use-case, requirement, or decision it serves. A doc that states only a *what*, with no why, is a defect. The fix is binary: **repair it** (add the why, citing its provenance doc if the rationale lives there) or **remove it**.

## Rationale

This is the operational enforcement of [[20260625222613]] (capture the why, not the what). The code already holds the what; a doc that merely restates it adds drift surface — one more thing that can fall out of sync — without adding any knowledge that would survive a rewrite.

Agents left to ingest or garden without this rule reliably fixate on implementation detail and reproduce the code in prose. That is the observed failure mode: a pass yields many docs, most mis-typed, almost none carrying a why. Making "what without why" an explicit defect gives ingest and gardening a concrete test to apply rather than an aspiration.

**Signposts are the one exception.** A grouping/index doc may exist purely to organize its children and orient a reader; its justification *is* the navigation it provides. For every other doc, if removing it would lose no why, it should be removed — see [[20260624224407]] (delete when redundant).
