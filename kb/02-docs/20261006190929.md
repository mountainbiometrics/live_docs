## Requirement

Each doc type carries a table of desired properties: which facets a doc of that type must have, may have, and should not have, and which `requires` edges it is expected to have. The facets are `intent`, `force`, `realization`, and `imposed_by`; each facet's own doc names the types it applies to, and the expected edges form the why-chain.

The table's terms, as tooling applies them:

- **Required** — the tool refuses to write a doc of that type without the facet. An existing doc missing it gets a validate warning.
- **Expected** — a missing facet or edge gets a validate warning.
- **Forbidden** — the facet's presence is a validate error.

Grouping types into kinds — purposes, norms, realizable things — is a property of each type's definition. No doc carries a separate tier field.

## Why

Types carry semantic meaning that matters to the system, but they were only labels. A table of desired properties per type is how they get used for something mechanical: a component or a decision tracks whether it is implemented, and a principle does not. That per-type knowledge is what an agent syncing code and docs relies on to know which docs to check ([[20261006190925]]).
