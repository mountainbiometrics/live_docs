## Context

idea_dump identified a need to disambiguate between "a coding principle that is useful in general" and "a coding principle that is vital for our current architecture": a relevance or generalizedness axis. The doc facets each answer a different question (who brought a claim forward, how hard it binds, whether it is built), and none of them encodes how narrowly a claim is scoped to the current situation.

## Decision

There is no relevance or generalizedness field. `scope` tags partially serve the need: a principle tagged `scope: [PaymentsService]` is visibly narrower than one tagged `scope: [live_docs]`. Whether a dedicated field is needed stays an open question, settled if broadly useful principles keep getting confused with context-specific ones.
