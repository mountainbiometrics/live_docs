The post-hoc review subsystem: why official docs must be reviewable, how reviewers read change summaries rather than diffs, and the queue/signoff mechanics.

The reason the subsystem exists is `[[20260616181705]]` (Reviewable Official Docs): official live_docs must be reviewable. Its defining stance is `[[20260616181719]]` (Review Post-Hoc) — review records a change after the fact and never blocks it. What reviewers actually read is set by `[[20260616181728]]` (Review the Summary): a synthesized change summary, not raw diffs, materialized as the ledger component in `[[20260616181820]]` (Review Summary). The mechanics follow: `[[20260616181738]]` (Review Queue Orthogonal) keeps the queue apart from the docs it tracks, `[[20260616181747]]` (Signoffs Multi-Reviewer) makes signoffs per-reviewer and multi-party, and `[[20260616181755]]` (No Auto-Bless) refuses any confidence threshold that would auto-approve a change. `[[20260616200145]]` (Dry Run as Summary) closes the loop: a mutation can be previewed as the same review summary before it lands.
