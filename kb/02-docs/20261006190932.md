## Requirement

When a doc's claim is something an implementation can realize, the store records whether it has been. For a component or an architectural decision it is relevant to ask, record, and keep track of whether it has actually been implemented. A principle simply exists, whether or not any implementation adheres to it, and carries no such record.

## Why

Doc types should be used for something, and this is the first use: the type tells the store which docs have an implementation state to track. Knowing which buildable claims are realized is also what an agent needs to sync code and docs in both directions ([[20261006190925]]).
