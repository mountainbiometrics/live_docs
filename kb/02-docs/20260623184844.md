## Decision

The **sole trigger** for shard-clipping (gate 1.5) to split a raw clipping is concept **VOLUME**: would the clipping decompose into **more atomic docs than one gate-2 ingest pass can comfortably comprehend AND synthesize**? The floor is deliberately generous — roughly **~50 atomic docs**. Below it, the clipping passes through unchanged; only well above it does shard-clipping split.

## Topical disjointness is explicitly NOT a trigger

The number of distinct subjects a clipping spans does **not** decide whether it shards:

- A clipping entirely about **one subject** still shards if it is big enough (its single subject decomposes into far more than ~50 atomic docs).
- A clipping spanning **many unrelated subjects** still **passes through** if it is small (the whole thing fits one comprehend-and-synthesize pass).

Disjointness and subject-count are therefore irrelevant to the shard/pass-through decision. They matter in **only one** place: deciding **where to cut**, once volume has already forced a split. That cut-placement role is the verbatim-passage-gathering-by-concept-cluster method (`[[20260623175240]]`); the *whether-to-cut* question this decision answers is upstream of it.

## Canonical example: idea_dump.md passes through

This repo's own `idea_dump.md` decomposes into roughly **~35 atomic docs** spanning many subjects — the doc model, the graph model, doc lifecycle, the founding principles, prior art. Despite that topical sprawl it is **under the volume floor**: one agent reads the whole thing and decomposes it in a single pass without strain, so it **passes through unsharded**. A prior, disjointness-based heuristic wrongly leaned toward sharding it precisely *because* it spanned many subjects; reframing the trigger as volume is the fix for that bug.

## Rationale

The purpose of sharding is to survive a genuinely **over-large** document — a 10k-line mega-doc, a sprawling spec — that one context cannot both comprehend and synthesize. It is **not** to break up normal-size multi-topic notes, which one pass handles fine. Volume is what overruns a context; topic-count does not. Tying the trigger to volume keeps sharding rare (its intended cost profile) and reserves it for the case it was built for.
