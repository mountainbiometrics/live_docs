## Decision

When `ldoc` resolves a store whose location is a url ([[20260916171913]]), it reads that store by acting as an **MCP client** of the host serving it: it calls the same tools an agent harness calls, and shapes the answers into the output its local reads produce. A read command behaves the same for its caller whether the store is a directory or an address.

## Why

Skills and consumer repositories reach a store by running `ldoc`, so a url has to be a location the store's own tooling can resolve. The host answers reads over one protocol ([[20260916171907]]), and speaking that one keeps the host a single thing to serve and to secure.
