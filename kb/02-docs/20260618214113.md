## Overview

A digest of a working session in which decisions about live_docs's own evolution were made AND implemented in this repo, but not yet recorded as docs. It is the first run of the reconcile-changes process, and the provenance anchor for the atomic docs decomposed from it.

The captured priority is the **abstract, non-recoverable knowledge** — principles, goals, use-cases, constraints, and the rationale behind each decision. Implementation-level facts (what the code now does) are recoverable from the code / README / AGENTS and are recorded only lightly.

## What the session decided

- **Principles:** borrow only incidental prior-art conventions, with explicit local decisions winning; navigation grouping and summarization are agentic judgments, not mechanical rollups; one schema authority (ldoc mutates, external tools observe read-only); skills compose via shared sub-skills rather than duplicated prose.
- **Goal:** the store must be navigable as a visual graph in Obsidian.
- **Use-cases:** one store documenting many external code repos (multi-repo deployment); reconciling a working session's already-live decisions into the store; dogfooding the system by evolving it on itself.
- **Decisions (already implemented):** configurable box paths; flat top-level `domain`/`scope` fields; a three-descriptor model (label, title, summary); boxes colocated under `kb/` with numbered distillation stages; the two-gate inbox pipeline (capture → promote(raw) → ingest(docs)); a stubbed root index with no per-type definition docs.
- **Open:** how to keep target-vs-living honest over time was analyzed but the decision is paused; only the multi-repo force (the use-case) and the finding that no reliable autonomous detection exists are durable.

## Provenance artifacts

The session produced three design-support reports — `reports/skill-composability.md`, `reports/target-actual-tracking.md`, `reports/obsidian-plugins.md` — which live outside the KB graph. Docs anchor their provenance to this digest rather than to those reports.
