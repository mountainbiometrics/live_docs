## Requirement

Before writing any changes, the `apply-to-docs` skill must evaluate the total blast radius of the request's impact on the store (read-only survey). It writes what the person just asked. It pauses only when the impact looks outside that ask.

## When to pause

**Unintended side-effects** — impact that looks outside what the request implies (cascade into an unrelated cluster the request never touched). Large counts of revisions on docs that clearly belong to the request are not a pause reason.

## When not to pause

Do not pause because the request supersedes an earlier doc, including a previous request or a `must`. Update those docs. In the reply, name the supersession and ask whether the two should have been merged instead ([[20261006190940]]). Do not halt because the impact set is large. A frozen doc that cannot be rewritten is named; it does not block the living updates.

## Warning format (when pausing)

The warning states why this is not just proceeding with the request, and lists the surprising impact. Expected supersessions are not in that list; they are in the reply, and the writes proceed.

## Rationale

The gate exists to catch a change that reaches somewhere the person did not mean. Using it to re-approve a supersession they just stated treats the store as a guardrail. The earlier doc is how the reply can say what changed.
