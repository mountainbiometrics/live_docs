## What this component covers

Viewer Architecture holds the foundational decisions that define what the viewer IS — its contract, constraints, and the invariants that shape every downstream implementation detail. Read these before the interface components (Dashboard, Reader, Catalog, etc.); they set the load-bearing properties the components must respect.

## The core contract

The viewer consuming a **pure-data export** ([[20260619204742]]) is the central invariant. Each doc is frontmatter-as-JSON plus raw markdown body; no server-side rendering, no precomputed HTML. Markdown renders client-side. This keeps the viewer's presentation layer swappable — future Phoenix or ld-serve paths consume the same export without changes to the store.

The artifact is **self-contained** ([[20260619204803]]): a single HTML file with docs inlined as a JS array, running from `file://` with no server. It is a build artifact and is never committed; `docs/` remains the source of truth.

## What the viewer does NOT do

The viewer is a **dumb read-only projection** ([[20260619204821]]): it renders, never writes, carries no judgment. All logic lives in the porcelain and CLI — this is the presentation-layer expression of the one-schema-authority constraint. The v1 read-only boundary ([[20260619204918]]) formalises this: writes are surfaced as copy-paste CLI snippets; future optional paths (ld-serve, Phoenix) preserve the same export invariant.

The decision to build a **purpose-built viewer** rather than use Obsidian ([[20260619204802]]) flows from the same principle: Obsidian leaks opaque ids and resolves wiki-links inconsistently. The purpose-built viewer resolves every link in a single client-side pass.

## Navigation and integration

The viewer offers **three orthogonal navigation modes** ([[20260619204849]]): hierarchy (belongs_to sidebar), facet (Catalog table), and graph (edge-aware neighborhood in the Reader side panel). Hierarchy and facet are daily drivers; the graph is always on beside the focus rather than a separate page. Store-local **`[viewer]` branding** ([[20260710235233]]) and **nav demotion of reference/archived docs** ([[20260710235236]]) are presentation invariants of this architecture.

The **porcelain auto-rebuilds** the viewer ([[20260623191806]]) after any doc or review mutation — silent by default, skippable via flag or env var, and non-blocking on failure. This keeps the artifact current without user ceremony.

The navigability **goal** this architecture serves ([[20260618214213]]): the store must be explorable through a dedicated reader where nodes read as `{type}: {label}`, edge types are visually distinguishable, and summaries are reachable on hover.
