**The live_docs system** is the top-level component of the store — the root of the `belongs_to` hierarchy, so everything else topologically lives within it. It is not a special "index" type: it serves as the primary navigational signpost purely because it has descendants. Pick the nearest subsystem below, or navigate directly via `ldoc find` / `ldoc ls` and the typed edges between docs.

It **anchors the root scope**: the value it declares on `scope` is inherited down its entire `belongs_to` genealogy, so every doc in the store carries the root scope as part of its effective scope unless and until a nearer ancestor adds a narrower facet.

The structural subsystems beneath it cover the foundational requirements the system derives from (`[[20260618230214]]`), the edge and graph model that connects docs (`[[20260618230215]]`), a single doc's lifecycle and schema (`[[20260618230216]]`), the post-hoc review subsystem (`[[20260618230223]]`), the ingest and inbox pipeline (`[[20260618230224]]`), the ldoc porcelain and CLI (`[[20260618230225]]`), the store layout and configuration (`[[20260618230226]]`), the optional read-only viewer (`[[20260619204727]]`), and the gardening maintenance pass (`[[20260626174000]]`). Each is itself a scope-anchoring component. Start with the foundational requirements to understand the bedrock the rest builds on.

Three use-case docs at the root level capture how the system is deployed and maintained. `[[20260618214247]]` (Dogfooding) explains why live_docs is developed by documenting its own evolution with its own tools — design conflicts surface early while still cheap to change, because the builders feel every rough edge directly. `[[20260618214227]]` (Multi-repo Deployment) describes the target production deployment: one store documenting many separate code repositories, and the force that creates for manual upkeep rituals when tooling cannot observe implementation. `[[20260618214238]]` (Reconcile A Session) covers the most common write pattern: a working session has moved reality ahead of the docs, and the store must catch up by capturing the *why* of decisions already made and already real.
