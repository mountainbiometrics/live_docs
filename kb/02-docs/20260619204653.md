A strategy conversation specifying an OPTIONAL, read-only HTML viewer layered on top of the live_docs KB. The docs storage stays presentation-agnostic and unchanged.

The viewer is purpose-built (replacing the earlier Obsidian-as-reader approach), driven by a pure-data export contract — each doc is its frontmatter as JSON plus a `body` field of raw markdown, rendered client-side. It ships as a single self-contained `file://` HTML build artifact (not committed; docs/ stays the source of truth). It is a dumb read-only projection: all logic stays in the porcelain, and writes are never performed by the viewer.

Wiki-link rendering is unified through a client-side id->{label,summary} resolver: `[[id]]` renders the label with a summary tooltip, `![[id]]` transcludes a body inline. `type:index` docs are the presentation-layer recombination mechanism (orientation-guide body plus on-demand inlined member bodies via belongs_to). Navigation offers three orthogonal modes (hierarchy, facet, graph) and four escalating inlining tiers (hover, single-click expand, index composition, double-click navigate). The viewer is strictly read-only for v1; write actions are surfaced as copy-paste CLI snippets. The pure-data export contract is the load-bearing invariant keeping future `ld serve` and Phoenix paths open.
