The **viewer subsystem** is an *optional, read-only* reader layered on top of the live_docs store. The store itself stays presentation-agnostic and unchanged; everything in this grouping is additive. Read this guide to get oriented before diving into any member.

## The spine

Two members carry the load-bearing ideas:

- **Pure-Data Export Contract** (`[[20260619204742]]`) is the spine. The viewer consumes a *pure data* export — each doc is its frontmatter as JSON plus a `body` of raw markdown, rendered client-side, with no baked HTML. This is what keeps presentation swappable and is the invariant every other piece depends on.
- **Purpose-Built Viewer** (`[[20260619204802]]`) is the framing decision: build our own read-only reader rather than rely on Obsidian, so every reference resolves consistently in one render pass. This supersedes Obsidian as the chosen reader for the broader navigability goal.

## How it ships and behaves

- **Self-Contained Viewer Artifact** (`[[20260619204803]]`) — one `file://` HTML file with docs inlined, no server/network, and *not committed* (a build artifact; docs/ stays source of truth).
- **Dumb Read-Only Projection** (`[[20260619204821]]`) — the viewer renders and never writes; all logic stays in the porcelain. This is the presentation-layer expression of logic-in-scripts and one-schema-authority.

## Rendering and reading model

- **Unified Link Resolution** (`[[20260619204822]]`) — one client-side resolver fed by an id→{label,summary} map: `[[id]]` renders the label with a summary tooltip, `![[id]]` transcludes a body, identically across every surface.
- **Index Recombination** (`[[20260619204840]]`) — `type:index` docs recombine decomposed docs into readable wholes *at view time*, resolving the decomposition-vs-colocation tension without colocating on disk.
- **Escalating Inlining Tiers** (`[[20260619204904]]`) — because docs are tiny, navigation should be rare; four tiers (hover → expand → index composition → navigate) let a reader pull in what they need mostly in place.
- **Three Navigation Modes** (`[[20260619204849]]`) — hierarchy and facet are the daily drivers; the graph view is additive and deferred.

## Scope and future

- **Read-Only V1** (`[[20260619204918]]`) — v1 is strictly read-only; writes (e.g. review signoff) are surfaced as copy-paste CLI snippets. Future `ld serve` and Phoenix paths stay open *because* they consume the same pure-data contract.
