The viewer subsystem is an optional, read-only reader layered on top of the live_docs store. The store itself stays presentation-agnostic and unchanged; everything in this grouping is additive.

Two members carry the design spine. `[[20260619204742]]` (Pure-Data Export Contract) is the invariant: the viewer consumes a pure-data export — each doc is its frontmatter as JSON plus raw markdown, rendered client-side, with no baked HTML. This is what keeps the presentation swappable and is the one thing every other piece depends on. `[[20260619204802]]` (Purpose-Built Viewer) makes the framing decision: build a dedicated read-only reader rather than rely on Obsidian, so every reference resolves consistently in one render pass.

How it ships and behaves: `[[20260619204803]]` (Self-Contained Viewer Artifact) — one file:// HTML file with docs inlined, no server or network, and not committed (a build artifact; docs/ stays the source of truth). `[[20260619204821]]` (Dumb Read-Only Projection) enforces the principle: the viewer renders and never writes; all logic stays in the porcelain.

The rendering and reading model: `[[20260619204822]]` (Unified Link Resolution) — one client-side resolver fed by an id→{label,summary} map, so `[[id]]` renders consistently across every surface. `[[20260619204840]]` (Subtree Recombination) extends this to descendant-bearing docs: they recombine their subtree at the presentation layer, resolving the decomposition-vs-colocation tension without colocating on disk. `[[20260619204904]]` (Escalating Inlining Tiers) — because docs are tiny, navigation should be rare; four tiers (hover → expand → subtree recombination → navigate) let a reader pull in context mostly in place. `[[20260619204849]]` (Three Navigation Modes) — hierarchy and facet are the daily drivers; the graph view is additive and deferred. Within hierarchy, `[[20260623215558]]` defines sidebar nesting, stateful tree behavior, and expand/collapse defaults; `[[20260624204545]]` (Catalog View) owns the facet table and its click-to-filter UX (`[[20260624204552]]`); `[[20260624202025]]` and `[[20260624204553]]` govern cross-surface facet display and enum formatting. `[[20260623215600]]` defines the default type-then-label sort wherever no surface-specific order applies. `[[20260619204918]]` (Read-Only V1) — v1 is strictly read-only; writes are surfaced as copy-paste CLI snippets.

Three members address context and constraints. `[[20260618214213]]` (Navigable Store) is the goal the viewer serves: the store must be explorable with nodes reading as {type}: {label} and edge types visually distinguishable. `[[20260618214139]]` (Grouping Is Agentic) sets the division of labor: deciding which docs form a coherent group and writing an aggregated overview are acts of editorial judgment by skills — the viewer renders what skills have synthesized, not a mechanical concatenation. `[[20260619235049]]` (Structural Entry Points) closes the circle: with the index type retired, viewer entry points must be derived structurally — roots of large subtrees, scope-anchoring components — not from type:index.
