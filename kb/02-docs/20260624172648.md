## Statement

A doc has single responsibility only when exactly **one** doc is in charge of a claim. If three docs each partially address the same claim, none of them is the real owner — and an unowned claim drifts.

Single responsibility has two faces:
- **Scope face** (the classical form, 20260615100003): a doc should have exactly one reason to change. If it has two, split it. The repair is *decompose*.
- **Ownership face** (this principle): a claim should have exactly one responsible doc. If the claim is spread thin across several docs with no single one fully owning it, consolidate it. The repair is *collapse* (merge or fold).

## Why this matters

Decompose and collapse are not opposed — they operate on different failure modes. A doc can be correctly scoped (one reason to change) but still fail the ownership test if a sibling doc redundantly re-asserts the same claim. Conversely, merging two partially-overlapping docs can create a decompose smell if the survivor now has two reasons to change. Each test must be run independently; neither subsumes the other.

## Repair moves

- **Merge:** two or more docs assert the same claim → pick a survivor, port unique content, deprecate the rest. Triggered by semantic overlap / duplication.
- **Fold:** a thin or incidental doc adds nothing standalone and can be absorbed into its parent without making the parent less singular. Triggered by low standalone value and absence of dependents — not semantic overlap. Safe only when the fold does not give the parent two reasons to change (would-it-trip-decompose is the guard).
