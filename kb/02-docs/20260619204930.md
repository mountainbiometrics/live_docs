## Constraint

`ldoc review sign` currently requires the **full review id** as an argument, with **no completion or selection affordance** (no "sign the latest", no pick-from-list, no prefix completion).

## Why it matters

This is the exact command the read-only viewer surfaces as a copy-paste snippet for review signoff, so the friction lands on a real user flow: the user must obtain and paste a full opaque id by hand. It is a minor but genuine ergonomic rough edge worth a future cleanup — e.g. accepting a prefix, offering a selection list, or defaulting to the most recent open review.
