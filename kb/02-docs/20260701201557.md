## Decision

A history entry records the **session** that produced it — the editing episode's explicit id — in a `session` field alongside the existing `at` timestamp. `session` is optional metadata on the entry; it does not replace `at`, and an entry written outside any open session omits it.

## Why

Episode membership was previously reconstructed by scanning for history entries inside a start→now timestamp window. Stamping each entry with its session id makes membership **exact and self-describing**: an entry belongs to an episode iff it carries that session id, independent of wall-clock overlap between concurrent episodes or skew between the recorded start and an entry's timestamp.

## Back-compatibility

The field is purely additive. History entries written before sessions existed carry no `session` and remain valid — no migration of the store is required. This is what lets session-selection and the legacy timestamp-window selection coexist.
