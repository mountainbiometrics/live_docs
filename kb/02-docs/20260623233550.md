Decompose the monolithic garden skill into a thin dispatcher over a family of independently-runnable, individually-tunable garden-* sub-skills (decompose, collapse, hierarchy, summarize, domains, refine, integrity), mirroring the ingest pipeline's 'shared phases become named non-user-invocable sub-skills; orchestrators are thin compositions' pattern. Reconcile curate-grouping and summarize-descendants into that same family (curate-grouping is absorbed by garden-hierarchy, which also folds in scope-anchoring and adds re-scoping of overgrown branches; summarize-descendants is renamed garden-summarize with an alias kept). Drop standalone staleness as a pass — it never writes and cascade-check already owns dependency-changed-after-dependent; its kernel becomes a dispatcher triage signal. Add a single shared belongs_to-placement prose include (text, not a skill) that synthesize-doc-changes applies at doc creation so a new doc is born with a semi-adequate parent, with garden-hierarchy refining placements later using full-store context — i.e. ingest originates placements and gardening refines them rather than originating all of them. Add a new keywords frontmatter field — a flat, non-inherited, non-cascade findability list distinct from domain, with ldoc new/set --keywords and ldoc find term-matching it — curated by garden-refine. The garden dispatcher is the sole user-facing entry point and owns the whole episode: the single START timestamp, routing (no-arg triage, natural-language intent, or 'all' full sweep in dependency order), one cascade-check over the union of changed docs, and the one ldoc review new; sub-skills are pure phases that report changed ids and own none of that bookkeeping.
