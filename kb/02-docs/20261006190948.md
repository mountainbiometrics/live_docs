## Decision

Each doc type expects `requires` edges to the docs that supply its why. Any one of the listed types satisfies the expectation:

| Type | Expected `requires` |
|---|---|
| goal | none |
| use-case | a goal |
| principle | a goal or use-case |
| constraint | when `imposed_by: tradeoff`, the decision or component it follows from; when `imposed_by: choice`, a goal, use-case, or principle |
| requirement | a goal or use-case |
| decision | a principle, constraint, requirement, goal, or use-case |
| component | a decision, principle, constraint, requirement, goal, or use-case |
| guide | a decision, principle, constraint, requirement, goal, or use-case |
| heading | none |
| reference | none |

Read bottom-up, the edges form the why-chain: components and decisions rest on norms (principles, constraints, requirements); norms rest on purposes (goals, use-cases); purposes require nothing. A purpose is also a root for a decision, component, or guide, so a choice whose only stated reason is a goal or use-case requires that purpose directly. A norm is written when a source states it or the choice is unintelligible without it, not to fill the middle of the chain. A doc that rests on both a norm and a purpose requires both.

A heading asserts only the grouping of its children ([[20261007193653]]), so it expects nothing too. Validate warns when a doc has none of its expected types upstream. A norm with no goal or use-case above it is the loudest signal for gardening.

The chain is expressed as expected edges per type, rather than a tier field on each doc, because which tier a type belongs to never varies from doc to doc.

## Why

Decisions and components should almost always depend on principles, constraints, or requirements, which should in turn almost always depend on goals and use-cases, two types that should be written far more often than they are. A goal or use-case is itself a root a later challenge has to re-weigh ([[20260707170659]]), so a choice whose only stated reason is a purpose has a why ([[20260625222613]]). Inventing a norm to fill that gap would record a rule the source did not state. Expecting a root per type makes a missing why visible. The norm edge, added only when the choice actually rests on that norm, is what lets cascade reach the choice when the rule changes. A heading has no such root: the grouping is its justification ([[20260625222638]]).
