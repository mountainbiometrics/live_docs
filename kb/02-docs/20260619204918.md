## Decision

The viewer **renders**; it performs no writes. When a workflow needs one — the motivating case is **review-queue signoff** — the viewer surfaces a **copy-paste CLI snippet** (e.g. `ldoc review sign <id>`) that the user runs in a terminal. The write still flows through the porcelain, the sole mutation path.

## A viewer that writes

A viewer that offers a write performs it through the porcelain, the same path the snippet takes, and it consumes the same **pure-data export contract** ([[20260619204742]]) this viewer consumes.

## The invariant that keeps that open

The export contract is the **load-bearing invariant**: every renderer reads the same pure data, so a write-capable one can be added without reshaping the data or disturbing this viewer. Keeping the viewer a renderer costs nothing in that optionality, because what such a renderer depends on is the contract.
