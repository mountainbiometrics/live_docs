Store configuration gains a base key (KB parent with numbered box defaults) and an extends/include key that fully delegates to an external .live_docs.toml — a consumer code repo is not a live_docs store, only a marker. Terminology is standardized: STORE_ROOT is where the KB and generated artifacts (e.g. build/viewer.html) live; CONSUMER_ROOT is where the discovered local marker lives. Local store path keys on a delegating marker are ignored; future consumer-only keys (e.g. default scope) may remain on the marker.
