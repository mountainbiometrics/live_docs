## Capability description

`ldoc` is the unified porcelain over the live_docs markdown store. It ships as two surfaces:

1. **`ldoc`** — shell command (`bin/ldoc` → `scripts/ldoc.py`), on `PATH` inside the repo via mise; fallback: `python3 scripts/ldoc.py <subcommand>`.
2. **`KB` class in `scripts/livedocs.py`** — importable for skills and scripts that need programmatic access.

### Read surface

| Verb | What it returns |
|------|-----------------|
| `get <ref>` | Frontmatter summary for a doc |
| `body <ref>` | Plain body text of a doc |
| `show <ref>` | Full doc with edges resolved to human labels (never bare ids/filenames) |
| `find <query>` | Search/filter docs by type, tag, or text |
| `ls [--type T]` | List all docs, optionally filtered by type |
| `resolve <ref>` | Resolve id, label, or title substring to canonical id |
| `label <ref>` | Print `<Type>: <Title>` label for a ref |

### Graph surface

| Verb | What it does |
|------|--------------|
| `neighbors <ref>` | Show direct depends_on and reverse-dependent neighbors |
| `graph <ref>` | BFS traversal over depends_on edges from a starting doc |

### Dumb mutators

Mutators carry NO judgment — they apply the requested change and nothing else. Skills (`revise-doc`, `ingest-reference`, `cascade-check`, `garden`) decide when to cascade, add history, or dedup.

| Verb | What it does |
|------|--------------|
| `new` | Create a new doc with frontmatter and optional body |
| `set <ref> --field value` | Update scalar frontmatter fields on an existing doc |
| `link <ref> --depends-on <ref2>` | Add edge(s) to a doc |
| `unlink <ref> --depends-on <ref2>` | Remove edge(s) from a doc |
| `history <ref> --add "<entry>"` | Append a history entry to a doc |
| `ingest-raw` | Write verbatim content into the raw/ tier (outside the graph) |

### Maintenance

| Verb | What it does |
|------|--------------|
| `validate` | Run structural integrity checks across all docs |
| `reindex` | Rebuild `docs/.index/` artifacts (hierarchy, dependents, orphans) |
| `edges` | Print forward and reverse edge maps |

### Ref resolution

Every `<ref>` argument accepts: canonical id (e.g. `20260615230652`), label (e.g. `porcelain-api`), or title substring (case-insensitive, unambiguous match required). Multi-word labels are quoted on the CLI.

---

> **Knowledge vs implementation boundary:** this doc describes the *capability* of `ldoc`. The implementation lives in `scripts/livedocs.py` and `scripts/ldoc.py` and is kept in sync by humans and the panel — live_docs does not govern its own tooling.
