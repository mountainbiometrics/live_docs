## Capability description

`ldoc` is the unified porcelain over the live_docs markdown store. It ships as two surfaces:

1. **`ldoc`** — shell command (`scripts/ldoc.py`), on `PATH` via install.sh symlink; fallback: `python3 scripts/ldoc.py <subcommand>`.
2. **`KB` class in `scripts/livedocs/`** — importable for skills and scripts that need programmatic access.

Global flag: **`--no-viewer`** — skip the automatic viewer rebuild after mutating commands (see Maintenance).

### Read surface

| Verb | What it returns |
|------|-----------------|
| `get <ref>` | Frontmatter summary for a doc |
| `body <ref>` | Plain body text of a doc |
| `show <ref>` | Full doc with edges resolved to human labels (never bare ids/filenames) |
| `find <query>` | Search/filter docs by type, tag, or text; term match covers title, label, body, and `keywords`. Optional `--keyword <term>` filter. |
| `ls [--type T]` | List all docs, optionally filtered by type |
| `map` | Entry points (signpost roots) with summaries — orient here |
| `resolve <ref>` | Resolve id, label, or title substring to canonical id |
| `label <ref>` | Print `<Type>: <Title>` label for a ref |

### Graph surface

| Verb | What it does |
|------|--------------|
| `neighbors <ref>` | Show direct edge neighbors by kind |
| `graph <ref>` | BFS traversal over cascade-hard edges from a starting doc |
| `edges` | Print forward and reverse edge maps |

### Dumb mutators

Mutators carry NO judgment — they apply the requested change and nothing else. Skills (`revise-doc`, `ingest-reference`, `cascade-check`, `garden`) decide when to cascade, add history, or dedup.

| Verb | What it does |
|------|--------------|
| `new` | Create a new doc with frontmatter and optional body; accepts `--keywords` (comma-separated, replace semantics — same shape as `--domain`) |
| `set <ref> --field value` | Update scalar frontmatter fields on an existing doc; `--keywords` replaces the doc's findability keyword list |
| `link <ref> --depends-on <ref2>` | Add edge(s) to a doc |
| `unlink <ref> --depends-on <ref2>` | Remove edge(s) from a doc |
| `history <ref> --add "<entry>"` | Append a history entry to a doc |
| `ingest-raw` | Write verbatim content into the raw/ tier (outside the graph) |
| `inbox add/list`, `promote` | Inbox pipeline gates 0 and 1 |

### Review ledger

| Verb | What it does |
|------|--------------|
| `review new --since <ISO>` | Create a post-hoc review summary for an editing episode |
| `review list [--unsigned-by <who>]` | List review records |
| `review show <ref>` | Show a review record |
| `review sign <ref> [--as <who>]` | Sign a review; default `who` from `ldoc config` user identity |

### User config

| Verb | What it does |
|------|--------------|
| `config user.name [<value>]` | Get/set the configured display name (git-style) |
| `config user.email [<value>]` | Get/set the configured email |
| `config signer` | Print the composite `Name <email>` sign-off string |
| `config --list` | List user preference keys |
| `config --bootstrap-from-git` | Copy user.name/email from `git config --global` if unset |

`ldoc config` does **not** require a located store. See user-config-identity.

### Maintenance

| Verb | What it does |
|------|--------------|
| `validate` | Run structural integrity checks across all docs; `keywords` are validated as free-text — trimmed and de-duped per doc, with no reference resolution |
| `reindex` | Rebuild `docs/.index/` artifacts (hierarchy, dependents, orphans) |
| `viewer [--out PATH]` | Build the read-only HTML viewer (also runs automatically after mutating commands — see below) |

**Auto viewer rebuild:** after any successful command that mutates **docs/** or **reviews/** (doc mutators and `review new` / `review sign`), `ldoc` rebuilds `build/viewer.html` silently by default. Disable per invocation with `--no-viewer`, or globally with `LIVEDOCS_AUTO_VIEWER=0`. Set `LIVEDOCS_AUTO_VIEWER_VERBOSE=1` for a one-line stderr notice. Rebuild failures are swallowed — porcelain must not fail because the viewer is stale. See `[[20260623191806]]` (Auto Viewer Rebuild).

### Ref resolution

Every `<ref>` argument accepts: canonical id (e.g. `20260615230652`), label (e.g. `porcelain-api`), or title substring (case-insensitive, unambiguous match required). Multi-word labels are quoted on the CLI. Pass `-` as the sole ref to read refs from stdin.

> **Knowledge vs implementation boundary:** this doc describes the *capability* of `ldoc`. The implementation lives in `scripts/livedocs/` and `scripts/ldoc.py` and is kept in sync by humans and the panel — live_docs does not govern its own tooling.
