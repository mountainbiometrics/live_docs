## Constraint

Registering a store name must **never silently rebind** that name to a different location. If a name is already registered to one path and something tries to register it to another, the attempt fails loudly rather than overwriting.

## Why

Silent last-writer-wins registration would let ordinary mistakes hijack a name: a second clone of the same repo, a copied repo whose config still carries the original `name`, a checkout moved without notice. Under an upsert, whichever store you last ran a command inside would silently repoint the name — spooky action at a distance, and non-deterministic in which one wins. Failing loud turns a silent hijack into a visible collision the user resolves once (by renaming or aliasing).
