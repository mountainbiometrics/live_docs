The owner asked for a refinement of the doc metadata model. `level` is removed and replaced by fields that each answer one question: `intent` (what the person did to make the claim exist: `requested`, `chosen`, or `incidental`), with `intent_basis` holding the quote or citation that backs any rung above incidental; `force` (how hard a normative claim binds: `must`, `should`, `may`); `realization` (whether the thing a realizable doc claims exists in the implementation: `realized`, `partial`, `planned`, `deferred`, `unassessed`), with optional `realization_refs` anchors and a `realization_verified` stamp; and `imposed_by` (what makes the claim hold: `environment`, `tradeoff`, `choice`). `status` keeps only the lifecycle values `living`, `deprecated`, and `reference`: deferral moves to `realization: deferred`, and a current path that coexists with its planned replacement carries `superseded_by` while still living.

Each doc type decides which of these facets it requires, allows, or forbids, and which `requires` edges it is expected to have, so the why-chain reads bottom-up: components and decisions require norms, norms require goals and use-cases, and purposes require nothing. Every doc line on every surface leads with the doc's intent and type and trails its force and realization, and listings rank by status, then intent, then relevance. Tooling is loose on input and strict on output. A sync skill keeps realization honest against the implementation, which lets agents sync coding work and design docs in both directions; implementation details are allowed as pointers and as a volatile `## Implementation` body section. Migrating existing stores is a follow-up.

The owner's reasons, in their own words, and the rulings they made during the session are archived verbatim at `raw/20261006185429.md`.
