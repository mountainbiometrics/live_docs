The bedrock principles every live_docs decision derives from. Start here to understand why the system is shaped the way it is.

Two principles state the system's *purpose*. `[[20260625222613]]` (Capture the Why, Not the What) is the thesis: the store records the why — decision process, use-cases, constraints, requirements — because the code already holds the what, and the why outlives any implementation. `[[20260625222638]]` (Every Doc Carries Its Why) is its enforcement: a doc that states only a what is repaired or removed, signposts excepted.

The next principle states the *method*. `[[20260625222626]]` (Docs as Code) treats design knowledge like well-factored code — atomic, single-responsibility docs that can be revised, superseded, or deleted one at a time with precision, never the replace-the-whole-blob model of conventional documentation.

The prime directive on *currency* is `[[20260615100001]]` (Living over Stale): docs must track current reality, the store is not an archive, and drift is the enemy worse than ignorance. `[[20260615100002]]` (Dependency Tracking) makes that drift checkable by recording explicit dependencies that trigger cascade checks, and `[[20260615100003]]` (Single Responsibility) keeps each doc to one reason to change — a wide cascade being the signal to split. `[[20260615100004]]` (Cognitive Load) shapes navigation around signposts and selective depth rather than front-loaded comprehensiveness, while `[[20260615100005]]` (Maintainability) insists the tooling maintain the docs, since systems relying on human discipline alone fail. Underpinning all of it, `[[20260615100000]]` (Tool Agnostic) keeps the store plain markdown on a filesystem, with git and Obsidian optional conveniences rather than requirements.

A final principle governs how the system borrows from prior art: `[[20260618214128]]` (Incidental Patterns) says to adopt only incidental conventions — directory naming, box layout, surface ergonomics — while explicit decisions in this system always override borrowed convention.
