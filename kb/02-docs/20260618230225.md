The ldoc porcelain: the KB-as-database access layer, its CLI surface, the descriptors and reference rendering it manages, its tooling architecture, integration boundaries, and its capability roadmap.

The founding decision is `[[20260615230652]]` (Porcelain API): treat the KB as a database accessed only through a porcelain API. `[[20260615230716]]` (ldoc CLI) is the component itself — the entry point for the subsystem. The descriptors it manages are set by `[[20260615230659]]` (Label and Title), where every doc carries three descriptors (label, title, summary), and `[[20260616200133]]` (Typed Wiki-Link Refs), where references render as typed wiki-links. `[[20260615204018]]` (Imported Timestamp) adds that reference docs carry an imported: timestamp separate from created:. The CLI's breadth is set by `[[20260616200121]]` (Batch Operations) — operations accept batch / multi-ref input — and its forward direction laid out in `[[20260616200300]]` (Porcelain Roadmap).

Three decisions govern the tooling architecture beneath the porcelain. `[[20260615185417]]` (Logic in Scripts) places all implementation logic in scripts/ — a shared module plus single-responsibility CLIs — with skill directories holding only thin wrappers that exec the script. `[[20260618214152]]` (One Schema Authority) makes the porcelain the sole mutation path: external tools (including Obsidian plugins) must be read-only, because write-back corrupts schema invariants and pollutes the change-trail. `[[20260618214203]]` (Skills Compose) sets the design principle for skills: shared phases are factored into non-user-invocable sub-skills the others invoke, not copied as prose — duplicated prose drifts; one authoritative definition does not.

Three docs address integration boundaries. `[[20260615100006]]` (Agent-Invoked Cascade) keeps cascade checks on-demand rather than wired into git hooks or CI, preserving tool-agnosticism. `[[20260615100018]]` (Panel Sensor) names the future sensor layer: panel subagents will detect code-to-doc drift and file cascade triggers into live_docs, composing cleanly with the porcelain — panel handles detection, live_docs handles storage and propagation — but panel integration is deferred to v2. A third boundary governs setup itself: `[[20260703005021]]` (Installer Sets Up The Tool Only) keeps installation tool-only — the `ldoc` CLI, skills, and per-user identity — while attaching a repo to a store (self-registration plus a one-line marker) stays a separate act, like `git` versus `git init`.
