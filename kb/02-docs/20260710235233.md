## Decision

An optional **`[viewer]`** table in the store's `.live_docs.toml` configures HTML viewer presentation and is **baked into** `build/viewer.html` at `ldoc viewer` build time:

- `title` — browser tab and navbar heading (default `live_docs`)
- `subtitle` — small subtitle beside the heading
- `favicon` — image path embedded as a data-URI
- `[viewer.domain_colors]` (alias `domains`) — domain tag → hex or `{bg,fg,border}` for pills and graph node strokes
- `[viewer.type_icons]` (alias `types`) — type → `{color, label, svg}` overrides for Lucide glyphs

Paths resolve relative to `STORE_ROOT`. Omitted keys keep built-in defaults; unknown types keep fallback icons.

## Why

Multi-store and branded deployments need presentation without forking the viewer. Like box paths, presentation is **store-local configuration**, not tooling code — the dumb projection stays one artifact; each store paints it.
