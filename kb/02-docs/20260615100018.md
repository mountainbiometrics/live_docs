## Context

D4 defers code↔doc tracking to a "panel sensor layer." That layer is the separate "panel" design: per-domain advisor subagents that watch code and detect drift.

## Decision

Panelists (panel subagents) are the sensor for code↔doc drift. When a panelist detects that code has drifted from documentation, it files a cascade trigger into live_docs. live_docs is the canonical store that panel v2's "actualize tribal knowledge into docs" step was reaching for.

## Consequences

The two systems compose cleanly: panel handles the detection problem (watching code); live_docs handles the storage and propagation problem (tracking what is known and keeping it current). Neither system needs to subsume the other. live_docs v1 ships without panel integration (D4); panel integration is the natural v2 upgrade that closes the code drift gap (P2).
