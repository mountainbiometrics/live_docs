## Context

The separate "panel" design consists of per-domain advisor subagents that watch code and detect drift.

## Decision

Panelists (panel subagents) are a sensor for code↔doc drift. When a panelist detects that code has drifted from documentation, it files a cascade trigger into live_docs. live_docs is the canonical store that panel v2's "actualize tribal knowledge into docs" step was reaching for.

## Consequences

The two systems compose cleanly: panel handles the detection problem (watching code); live_docs handles the storage and propagation problem (tracking what is known and keeping it current). Neither system needs to subsume the other. Within the store, the realization sync ([[20261006190952]]) checks realizable docs against the implementation; panel integration composes with it.
