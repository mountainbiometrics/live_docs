## Correction

**Superseded by [[20260701224958]].** That decision — Creation Is Recorded History — replaces this one. This doc held that `history:` excludes creation, that a doc's creation time lives in a separate `created:` field, and that `history: []` is a valid resting state. That no longer holds: creation is recorded as an `addition` history entry, the `created:` field is dropped, and every doc carries at least one entry. The churn-signal intent survives — `addition` entries are excluded from the count (see [[20260615203928]]).

## Decision (historical)

`history:` records only genuine CHANGES applied to a doc after it is first written. Docs are created with `history: []` (an empty list). The creation timestamp is captured by the `created:` field. No creation entry is emitted by `ldoc new` and none should be added manually at doc creation time.

## Consequences

- History becomes a meaningful churn signal: many entries indicate an ill-defined, multi-responsibility, or fickle area of the knowledge base.
- History length supports cascade-distance analysis and garden smell detection.
- `validate` does not require non-empty history; `history: []` is valid and normal.
