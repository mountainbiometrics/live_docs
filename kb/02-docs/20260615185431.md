## Context

During bootstrap, every doc was seeded with an "initial creation" history entry — e.g. `summary: "Initial creation during bootstrap"`. This made history non-empty but noise-filled: a creation timestamp conveys no signal about the doc's evolution.

## Decision

`history:` records only genuine CHANGES applied to a doc after it is first written. Docs are created with `history: []` (an empty list). The creation timestamp is already captured by the `created:` field. No creation entry is emitted by `new_doc.py` and none should be added manually at doc creation time.

## Consequences

- History becomes a meaningful churn signal: many entries indicate an ill-defined, multi-responsibility, or fickle area of the knowledge base.
- History length supports cascade-distance analysis and garden smell detection.
- `validate` no longer requires non-empty history; `history: []` is valid and normal.
- Existing bootstrap creation entries have been stripped from all docs.
