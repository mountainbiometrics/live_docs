## Decision

A store registered in the per-user registry ([[20260703002417]]) is bound to a **location**, and that location is either a **local root** — a checkout on this machine — or a **url**: the address of a host that serves the store, plus the name that host serves it under when it serves several.

Reads against a url location resolve through the host. A command that would change such a store fails loud and names the reason, the way an unresolvable store name does ([[20260703002418]]).

## Why

The name is the portable half of a store reference and the location is the half that varies per machine ([[20260703002413]]). A url is another kind of location, not another kind of reference, so a repository that commits `store = "<name>"` keeps working for a teammate who never checks the store out: the name resolves to a host for them and to a directory for someone holding the checkout, and nothing committed has to know which.

Read-only is a property of the location. What a host offers is a read surface ([[20260916171907]]), so a client that resolved a url has nothing to write through, and the failure is stated where the attempt is made.
