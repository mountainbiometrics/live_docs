Refinement of the shard-clipping (gate 1.5) design captured from a 2026-06-23 design conversation. The sole trigger for sharding a raw clipping is concept VOLUME: whether the clipping would decompose into more atomic docs than one gate-2 ingest pass can comfortably comprehend AND synthesize, with a deliberately generous floor of ~50 atomic docs. Topical disjointness / number of subjects is explicitly NOT a trigger — a single-subject clipping still shards if large enough, a many-subject clipping still passes through if small; disjointness only guides WHERE to cut once volume has forced a split. Canonical example: this repo's idea_dump.md decomposes into ~35 atomic docs across many subjects yet passes through unsharded. The purpose of sharding is surviving genuinely over-large docs, not breaking up normal-size multi-topic notes. Anchored to the shard-clipping design reference 20260623174829.
