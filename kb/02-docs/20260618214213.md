## Statement

A first-class way to explore the store is the **Obsidian graph view**. To make it useful:

- nodes read as `{type}: {label}` (not opaque ids),
- the distinct edge types are visually distinguishable,
- a doc's summary is reachable on hover.

## Rationale

The store is intentionally **atomic and id-opaque**, which makes flat directory browsing hard. A typed, labeled graph restores human navigability — a reader can see clusters, follow edge types, and read summaries without opening files.

## How the goal is met

Config-only wins (graph display settings, node labels) are applied directly. Richer needs are met by **read-only** plugins only — write-back plugins are excluded by the one-schema-authority constraint, so the graph layer enhances navigation without ever owning the data.
