Any LLM agent operating a live_docs store must be able to do so using only the ldoc CLI. Shell commands (rm, grep, find, cat, etc.) are not a valid fallback for missing CLI functionality, because:

1. Portability: agents may run in sandboxed environments where arbitrary shell access is unavailable or restricted.
2. Consistency: raw shell operations bypass the CLI's safety checks (e.g. ldoc rm checks for dependents before deleting; a bare rm does not).
3. Discoverability: if an operation is not in ldoc, an agent has no reliable way to know it exists or how to invoke it safely.
4. Orientation quality: default CLI surfaces (`map`, `find`, `validate`, …) are what agents explore and learn from. Demotion of reference/archived material ([[20260717210152]]) and refusal to mutate reference snapshots ([[20260717210153]]) must be CLI behavior — not documentation agents never see.

When an operation is absent from the CLI, the correct response is to extend the CLI — not to document a shell workaround. The delete operation was the first real instance of this constraint being violated: early guidance said 'rm kb/02-docs/<id>.md + ldoc reindex', which was fixed by implementing ldoc rm.

This constraint applies to the CLI surface only. The KB Python class (scripts/livedocs/kb.py) may be used by scripts and skills that run in the same process; that is not a shell-out and does not violate portability.
