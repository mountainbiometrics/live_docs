## Statement

Docs must describe what the system currently IS and must update alongside the things they document. Stale docs are worse than no docs.

## Rationale

A stale doc misleads confidently. It consumes trust faster than ignorance does: a reader acts on the stale claim, hits reality, and loses faith in the whole corpus. Drift is the primary enemy; every design decision in this system is evaluated first by whether it reduces drift.

## The store is not an archive

Living docs serve the currently-alive system, not historians or archaeologists. The store shows what *is*, not what *was* — so cleaning is liberal: dedupe, collapse, deprecate, and delete anything no longer part of the living system. Genealogy and superseded patterns belong in git history, present here at most as a tucked-away footnote; a reader who wants to dig through what the system used to be can always read the commits. This is why deletion is the default retirement path ([[20260624224407]]) and deprecation the exception.

How reference/archived material is demoted on store surfaces is owned by [[20260717210143]] — not restated here.
