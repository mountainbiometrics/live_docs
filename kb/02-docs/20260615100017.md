## Context

live_docs is being built inside a consuming store — a specific project. System-level docs (principles, decisions about the doc system itself) need to be separable from that instance's domain docs.

## Decision

System-specification docs live **under the root scope anchor** — the `live_docs` scope declared on the root component and **inherited through `belongs_to` lineage** — rather than each doc hand-carrying a `scope: [live_docs]` tag. Their **effective scope** therefore includes `live_docs` by virtue of where they sit in the hierarchy. Instance-specific docs accumulate in their own zone (their own scope anchor), outside the `live_docs` genealogy.

## Consequences

The system stays portable: live_docs can be extracted by lifting the subtree under the `live_docs` scope anchor, and effective scope (a topological computation) tells you cleanly which docs that is. Instance-specific knowledge does not pollute the generic system definition because it sits under a different anchor. The discipline shifts from "stamp the tag on every system doc" to "keep system docs in the live_docs genealogy"; a gardening skill can verify that placement.
