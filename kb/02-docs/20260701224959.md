## Decision

Every store **mutation** runs inside an open session. If none is set when a mutation is invoked, `ldoc` **auto-creates** one and announces it (printing the new id and the export line) rather than refusing — the change is still attributed, and the operator is told a session was opened. Read-only commands need no session.

## Accident guard

Setting the session id when one is **already** set in the environment is an **error**. Re-opening over a live session is almost always accidental — a nested `session start`, a stale export — and silently switching would mis-attribute every subsequent change.

## Fragmentation is merged, not prevented

Because each `ldoc` process is separate and cannot export back to its parent shell, repeatedly mutating without exporting the auto-created id yields several one-command sessions. That is expected and reconciled afterward by `session merge`, not prevented here.
