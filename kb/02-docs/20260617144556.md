## Context

The original live_docs spec described an 'influence/impact web' where cyclic relationships are meaningful. The word 'dependency' in early implementation language silently imposed DAG semantics — acyclicity at the graph level. Since a DAG subsumes hierarchy, the 'hierarchy' feature appeared to be the only thing deferred, while the intended web was dropped without being named.

## Decision

The live_docs graph allows cycles. Acyclicity is a property of individual edge *types*, declared in the type schema — not a property of the graph as a whole. Some types (e.g. belongs_to, requires, provenance) are acyclic because their semantics require it; others (e.g. relates) have no acyclicity constraint.

cascade-check handles cycles by detecting when a propagation reaches an already-updated doc (declared incompatible), not by forbidding cycles at the schema level.

## Consequences

- The validate skill enforces acyclicity per-type, not globally.
- Cycle detection in cascade-check is a runtime behavior, not a schema violation.
- Restores the influence-web intent: two principles can 'relate' to each other bidirectionally without violating graph structure.
