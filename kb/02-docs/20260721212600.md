## Context

Agent harnesses (Claude Code, Cursor, and whatever comes next) each require their own plugin manifest format and identifier rules. Skills are the agent-facing policy channel that must travel with the tooling ([[20260624225658]]). Duplicating the skill corpus per harness would create parallel sources of truth that drift.

## Decision

Skills live in **one shared tree**. Each harness receives only a thin harness-specific plugin manifest that points at that tree. Manifest identifiers and discovery paths may diverge as the harness requires; the skill content does not.

`install.sh` installs those manifests into whichever harnesses are already present on the machine, using each harness's native mechanism — it does not invent a harness home for one that was never opened ([[20260703005021]]).

## Why

The skill content is the product; harness packaging is incidental adapter. Keeping one tree preserves singular ownership of agent-facing policy. Thin per-harness manifests are how harness-agnosticism ([[20260707164524]]) *reaches* agents without coupling the corpus to a single harness — requiring Claude-only packaging would have been the coupling.
