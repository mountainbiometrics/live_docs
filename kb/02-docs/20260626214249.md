## Statement

Keeping the store consistent depends first on **detection** — finding the docs a change makes stale — and detection cannot rely on lexical search. A doc whose wording predates a new vocabulary is invisible to a query phrased in the new terms, so supersession must be found by **reasoning over the topological cluster** (the `belongs_to` / `scope` neighborhood of the change), not by keyword overlap.

## Rationale

Propagation — cascading updates along edges once a stale doc is identified — is the well-understood half of consistency. The failure in practice is upstream of it: the stale doc is never *retrieved*, so nothing propagates. Searching the store with the new claim's terminology guarantees missing exactly the docs written in the *old* terminology — which are precisely the ones most likely to be superseded. The remedy is to pull the whole cluster a change touches and ask, doc by doc, "given this new intent, does this still hold?" — reasoning, not lexical match.

**Red flag:** a system-changing initiative that supersedes *zero* existing docs is almost always a detection miss, not a conservative win. Treat a no-supersession result on a real change as a signal to re-examine the affected scopes, not as success.

This is drift-prevention applied to the detection step: drift is the enemy, and the first place it hides is in the docs a lexical search can't see.
