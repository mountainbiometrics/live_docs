## Decision

The capture→ingest pipeline records **three new optional provenance fields**, captured as early as **gate 0** (`ldoc inbox add`) and carried **losslessly forward through gate 1** (`ldoc promote`) onto the raw clipping:

- **`origin`** — the corpus or system the material came from (e.g. `notion`, `codebase:foo`, `codebase:bar`). This is the **namespace axis**: it distinguishes not merely the *medium* (Notion vs. code) but the *instance* (one repo vs. another). Two source files from two different codebases share a `medium` but differ in `origin`.
- **`medium`** — the medium of the source (e.g. `pdf`, `scan`, `notion-page`, `source-file`, `transcript`).
- **`authored_at`** — when the **source material** was written. It is allowed to be **fuzzy** (`2024-03`, `circa 2023`), because a scanned page or an old doc rarely carries a precise timestamp. The CLI flag is `--authored-at`; it is stored as `authored_at`.

All three are **optional** — capture must stay frictionless (async-inbox), so none of these block a drop. They are stamped at gate 0 when known and survive promotion unchanged.

## Rationale

The motivating use-case is ingesting **heterogeneous sources** — Notion pages, files from several distinct codebases, PDFs, scanned pages — into one store. Without an origin namespace, material from `codebase:foo` and `codebase:bar` is indistinguishable once captured. Without source-age, mixing a two-year-old doc with a two-week-old one erases the very signal downstream **staleness reasoning** needs. These fields give every captured item enough origin and age context that later reasoning about freshness works *across* sources of different provenance, not just within one.

## Latent fix folded in

The raw clipping `status` was previously written inconsistently as the **non-enum value `historical`** (in `ingest_raw.py` and at promotion) versus `reference` (in `kb.py`). It is standardized to the valid enum value **`reference`** — the same frozen-provenance status a raw clipping should carry.

## Deferred extensions (planned, not yet built)

These are intended next steps, recorded so the model leads reality:

- **Provenance onto the normalized reference doc.** Stamp `origin`/`medium`/`authored_at` onto the normalized reference (graph) doc at ingest too, so atomic docs extracted from it can reach the source-age via their `provenance` edge. Requires extending `REFERENCE_EXTRA_FIELDS` and `ldoc new`.
- **Raw ingest-state.** Give raw items an ingest-state (`pending` / `ingested`) plus a `raw list --pending` view, enabling deliberate batch processing of the backlog over time.
- **Shard-clipping pre-pass (gate 1.5).** A pre-pass that splits oversized clippings along concept seams into child raw clippings before ingest, to fix large-doc ingest stalls.
