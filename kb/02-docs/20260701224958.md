## Decision

A doc's creation is recorded as its first **history entry** — an `addition` (see the change-type taxonomy), stamped with the session that created it — rather than being left implicit. This **supersedes** the earlier rule that history excluded creation. Like every other change, the entry is **materialized at session close** from the WAL (history-from-wal), not written at `new` time.

## Consequences

- The separate `created` frontmatter field is **dropped**: a doc's creation time is the `at` of its addition entry, and the doc id already encodes it.
- Once a session closes, every doc it touched carries a history entry; a doc created within an **open** session has none until close (its creation lives in the WAL meanwhile).
- The addition entry is **excluded from the hot-file churn signal** — creation is not churn.

## Migration and back-compat

Existing docs are converted by a one-shot `ldoc migrate` (each `created` becomes an addition entry; the field is removed). Reads **tolerate** a lingering `created` — an outdated writer may still emit one — and stay **pure**, never rewriting on read. A doc is healed on its **next write** for any reason.
