## Context

Dependency edges between docs can be stored bidirectionally (each doc lists both what it depends on and what depends on it) or unidirectionally with the reverse computed.

## Decision

Only `depends_on` is stored in frontmatter. The reverse index (what depends on this doc) is a generated, rebuildable artifact — not a source-of-truth field.

## Consequences

Bidirectional storage would let the two assertions disagree, introducing a meta-drift problem: a form of drift inside the drift-tracking system itself (P2, P3). Single-direction storage with a generated reverse index is consistent by construction. Any tool rebuilding the index gets the same result. The cost is that dependents are not visible by reading one file — a lookup is required (P5 tradeoff, judged acceptable).

## Correction

This was the wrong take. Treating `depends_on` as the single edge field was an incidental consequence of "dependency" language implying DAG semantics — the intended model was always a typed influence/impact web where different relationships have different cascade behavior. The correct decision is [[20260617144634]].
