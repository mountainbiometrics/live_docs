Track each review episode by an explicit, generated session id rather than by reconstructing the episode from a START-timestamp window. The session is the existing episode concept made explicit and durable: an owner skill runs `ldoc session start` (minting a time-sortable id exported as LDOC_SESSION), every mutation logged during the session stamps that id into an additive `session` field on its history entry alongside the existing `at` timestamp, `ldoc review new --session <id>` builds the review by selecting exactly the entries bearing that id (with the legacy `--since` timestamp path retained as a coexisting fallback), and `ldoc session end --summary` finalizes the session with a human summary that becomes the review's summary. Session ids make episode membership exact where timestamp-window scanning misclassifies under overlapping episodes or clock skew; the review process is the store's primary human-in-the-loop mechanism, and its session-tracked mechanization is a precondition for letting agents churn the KB with less supervision. Design is additive and back-compatible — pre-existing history entries simply lack `session`, no migration required.
