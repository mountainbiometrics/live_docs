## Overview

A design session exploring live_docs graph structure and edge-type vocabulary. Started from dissatisfaction with exploration feeling clunky (no summaries, no signposts, no cluster identity), and converged on edge-typing as the keystone fix.

## The web vs. DAG realization

The system was intended as a bidirectional influence/impact web where cycles are legal. The word 'dependency' in the original spec silently made it a DAG, and since a DAG made hierarchy redundant, the web got skipped while it *looked* like only the DAG was deferred. This is the root disconnect. The fix is: cycles are legal in the graph; acyclicity is a property of individual edge *types*, not of the graph as a whole.

## Four felt-gaps, three underlying needs

| Felt-gap | Underlying need | A tree? |
|---|---|---|
| No overviews without scanning | Summaries / content rollups | No — v1 deferral, orthogonal |
| Clusters are incidental | Sparse graph (gardening) + no 'belongs together' edge | Partly |
| No signposts when search misses | Browsable entry points (curation) | Partly — index docs |
| Sub-principle-of vs. similar-to vs. constrained-by | Edge typing | No — schema gap |

Edge-typing is the keystone: it subsumes hierarchy (a tree spine is just the subgraph of structural edges), enables clusters (relates edges), and restores the web (cycles legal on non-acyclic types).

## Edge type vocabulary

The conversation iterated toward four active types (one reserved):

| Type | Dir | Cascade | Removal jeopardy | Structural? | Acyclic | Outside graph? |
|---|---|---|---|---|---|---|
| **belongs_to** | directed | both ways | yes (orphan) | YES | yes | no |
| **requires** | directed | yes (reverse strong) | yes (slate removal) | no | yes | no |
| **relates** | symmetric | no | no | no | n/a | no |
| **provenance** | directed | no | no | no | yes | YES |
| *(superseded_by)* | reserved | — | — | — | — | — |

'belongs_to' preferred over 'part_of' because 'part_of' implies compositional (not a real axis); 'belongs_to' more clearly carries the orphan implication.

'superseded_by' deferred — no supersession functionality exists yet.

## Why relates and provenance don't collapse

The user challenged whether 'references' (provenance) and 'relates' should be collapsed. Conclusion: no, three functional differences survive:
1. **Direction is the information** in provenance (B is the source, A the derivative; the arrow is the content). 'relates' is symmetric.
2. **Immutable fact vs. living judgment**: provenance records what happened at ingest and never changes. 'relates' is a current assessment; garden prunes stale relates edges but must never prune a provenance edge (you can't un-derive something).
3. **validate enforces provenance invariants**: every doc extracted by ingest-reference must carry a provenance edge. No analogous structural invariant exists for relates.

Resolution: rename 'references' to 'provenance' to make the semantic honest.

## The 'name it after behavior' principle

Throughout: name edge types after their *functional behavior* in the system (cascade semantics, removal jeopardy, acyclicity, validate rules), not after their conceptual category (hierarchical, associative, etc.). Derive the type set from the behavior matrix; collapse identical rows.
