## Decision

`ldoc store register --alias <name>` binds a store under a **user-chosen local name** instead of the store's declared `name`. It serves two purposes at once: it is the **escape hatch** when two distinct stores collide on the same declared name (register one under a different local alias), and it supports plain local-naming preference.

An alias lives only in the user's own config, so a **committed** consumer reference (`store = "..."`) will not see it — choosing an alias is opting out of team-portability, which is the user's own call. Auto self-registration always uses the store's declared name, so an alias is always a deliberate, explicit act.

## Rationale

Store-declares-name is right for committed, team-shared references, but it makes name collisions possible within one user's set of stores. Rather than force those to fail permanently, `--alias` is the deliberate resolution that fail-loud registration hands the user — and it recovers the local-alias flexibility (as in git remotes and AWS profiles) for anyone not sharing a committed consumer config.
