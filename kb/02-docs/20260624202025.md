## Context

The viewer already computed effective scope from the `belongs_to` genealogy and showed it as colored pills; `domain` tags were in the export but not rendered. Scope pills also listed every union member separately (`live_docs`, `viewer`) even though anchors form an ordered path along the hierarchy.

## Decision

On **every doc-preview surface** that shows facet context — Reader meta lines, link tooltips, inline expands, dashboard lists, member lists — the viewer surfaces **scope** and **domain** with equal prominence:

- **Scope** renders as a **breadcrumb trail** (`live_docs / viewer`): ordered anchor scopes along the doc's `belongs_to` chain root→leaf. Not a pill, not one chip per union member. Effective scope (the union) still powers Catalog **filtering**; only the label is path-shaped.
- **Domain** renders as **colored pills** for each tag on the doc. Domain is flat (not inherited); pill hue offsets from scope text so the axes read apart.

**Catalog-specific** table layout, column order, and in-row click-to-filter are owned by `[[20260624204545]]` (Catalog View) and `[[20260624204552]]`.

## Consequences

- Presentation lives in `scripts/viewer/template.html`; the pure-data export contract is unchanged.
- The store model (`effective scope = union along genealogy`) is unchanged; breadcrumb display is a viewer concern only.
