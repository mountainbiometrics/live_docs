## The test

Ask three questions of a claim:

1. Can an implementation realize it, so that it carries `realization` ([[20261006190943]])?
2. Is it a norm, so that it carries `force` ([[20261006190941]])?
3. Was it chosen, or imposed from outside ([[20261006190946]])?

Then:

- realizable, normative, and chosen → **decision**;
- realizable, not normative → **component**;
- normative, not realizable → **principle**, or **constraint** when it is imposed from outside.

A constraint is a norm imposed from outside that binds with `must`; the type is kept because "constraint" is useful vocabulary. Goals, use-cases, guides, and references are recognized by what they are.

The agent-facing copy of this test lives in the skills' doc-types definition, since skills are how policy reaches agents in other repos ([[20260624225658]]).

## Why

Types carry semantic meaning the system relies on, and the facets each type requires make that meaning checkable ([[20261006190929]]): a claim's type can be read off the facets it needs.
