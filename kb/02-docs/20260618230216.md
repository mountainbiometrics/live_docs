## What this component covers

Doc Lifecycle and Schema covers the definition and lifecycle of a single doc: what fields it carries, how it moves through states, when it retires, and what the field vocabulary means. Everything about a doc-as-database-row lives here.

## The type taxonomy

The type taxonomy defines what kind of knowledge a doc captures. Decision, principle, constraint, goal, guide, component, requirement, reference, use-case — each type has a distinct meaning and disciplined use. **Decisions are architectural**: choices among alternatives, scoped via `belongs_to` to the level they bind ([[20260625222655]]); keep them thin and wire them to why-web roots; the type is reserved to keep the taxonomy meaningful. The `index` type was retired ([[20260619234959]]): a doc serves the signpost role by having descendants, not by declaring a type.

## Facets and lifecycle

Each doc type decides which facets it carries and which `requires` edges it expects ([[20261006190929]]): `intent` records what the person did to make a claim exist, `force` how hard a norm binds, `realization` whether a buildable claim exists in the implementation, and `imposed_by` what makes a claim hold. `status` is lifecycle only: living, deprecated, or reference ([[20261006190947]]). `is_living` ([[20260617212550]]) is derived from status and governs only which docs cascade-check may rewrite. Interface demotion of `type: reference` / `status: reference` material ([[20260717210152]]) and porcelain immutability of those snapshots ([[20260717210153]]) are separate Store Interfaces rules. Deprecation ([[20260617212602]]) requires a `superseded_by` edge and a `## Correction` section, not just a status flip. Deletion ([[20260624224407]]) is the correct retirement path when content is fully captured elsewhere; deprecation is the exception.

## Fields and conventions

Key field decisions:
- History ([[20260615185431]]) is a change-trail, not a creation log — entries record why the doc changed, not that it exists.
- Relevance/generalizedness has no dedicated field; scope tags partially serve it ([[20260615203858]]).
- Silence is not ratification ([[20260723223658]]); unconfirmed agent suggestions stay `intent: incidental`.
- Empty list fields are omitted from frontmatter ([[20260617212613]]); absent means empty.
- Reference subtypes use a `kind` field, not separate top-level types ([[20260615100013]]).
- Provenance is required, and a provenance edge alone never raises a claim's intent ([[20260615100014]]).
- Durable names prefer the user's vocabulary over agent coinages ([[20260723223659]]).
- Hot-file signal ([[20260615203928]]): history length is the primary decomposition candidate signal.
- Stores move to a new structure through a normalized, repeatable process ([[20261006190928]]).

## The domain vocabulary

**Domain** ([[20260624185845]], [[20260615203839]]) is a finite, curated, governed set of tags — a shared resource where each tag earns its place as a distinct filterable grouping. A store ships with zero domains; they emerge from use. Writers reuse via `ldoc domains`; gardening refines authoritatively ([[20260624185902]]). Alongside domain filtering, docs are findable by full-text search over title, label, and body ([[20260716212859]]).

## Self-definition

Type documents ([[20260615100015]]) make the system self-defining: the type taxonomy is documented inside the store itself using the types it defines.
