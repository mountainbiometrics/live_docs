## Context

Schema enums (`type`, `status`, `intent`, `force`, `realization`, `imposed_by`) are stored as lowercase kebab/snake strings (`use-case`, `living`, `incidental`). Scope and domain values are an open, store-defined vocabulary with their own conventions. The viewer displays frontmatter widely — meta lines, tooltips, dashboard stats, catalog cells, dropdown labels — and raw enum strings read as implementation detail.

## Decision

The viewer **displays** `type`, `status`, and the facet values (`intent`, `force`, `realization`, `imposed_by`) in **Title Case** everywhere they appear (`use-case` → "Use Case", `living` → "Living"). **Scope and domain** values render **as stored** — they are governed vocabulary from the KB, not fixed schema enums.

Display formatting is presentation-only: filters, sort keys, and preset logic continue to use the raw frontmatter strings.

## Consequences

- Implemented client-side via a shared `enumDisplay` helper in `scripts/viewer/template.html`.
- Catalog click-to-filter chips carry raw values in data attributes; only the visible label is Title Case.
