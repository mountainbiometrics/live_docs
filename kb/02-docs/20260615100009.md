## Context

Code is the primary drift source for documentation. Tracking code↔doc edges would make cascade checks much more powerful. However, implementing code-reference tracking significantly increases system complexity and scope for v1.

## Decision

v1 tracks only doc↔doc edges via `depends_on`. Code↔doc tracking is deferred to the panel sensor layer (see D13).

## Consequences

Scope is contained (P4, P5): the core system stays small and shippable. The most common drift vector — code change without doc update — is not yet caught automatically. This is an accepted gap; it is addressed architecturally by the panel design rather than by bloating live_docs v1.
