## Context

Code is the primary drift source for documentation. Tracking code↔doc edges would make cascade checks more powerful, but edges into code would significantly increase the system's complexity and scope.

## Decision

Edges connect docs to docs only. A doc's relationship to the implementation is recorded on the doc itself, as its `realization` and the anchors in `realization_refs` ([[20261006190943]], [[20261006190944]]). Anchors are pointers, not edges: cascade never walks them.

## Consequences

The graph and cascade stay within the store, keeping the core system small ([[20260615100003]], [[20260615100004]]). Code that changes without a doc update is caught by the realization sync checking anchors ([[20261006190952]]), not by cascade.
