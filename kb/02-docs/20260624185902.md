## Context

A domain vocabulary can be pre-seeded or left to emerge. Seeding presumes what concerns a documented system has — but the documented *subject*, not live_docs, determines its domains, and no one can know them in advance. Left purely to a later pass, every doc is born untagged and the vocabulary drifts as each tagger independently coins synonyms.

## Decision

**Domains emerge from use, not from a seed.** A store ships with **zero** domains and does not presume any; an empty domain facet is a correct state, not a gap. Domains are **identified at tag time** — when a doc is created or placed, the writer applies whatever domains genuinely fit (an LLM reliably identifies which generic concerns a doc is about).

To keep the emerging vocabulary from fragmenting, tagging is backed by a **domain registry**: a way to list the domains already in use across the store (e.g. `ldoc domains`). At tag time the writer is **nudged to reuse an existing domain** from that list over inventing a new one; inventing is reserved for when nothing existing fits. This curbs synonym drift at the source rather than leaving it all to cleanup.

**Ingest originates, gardening refines** — the same division of labor as `belongs_to` placement. The writer originates a doc's domains cheaply and locally; gardening later refines the shared vocabulary (consolidating, reassigning, validating, normalizing) with full-store context. Both lean on the registry as the shared source of what already exists.

## Asymmetric bias: originate liberally, prune authoritatively

Because origination happens in **isolated context** and refinement in **full-store context**, the two carry *opposite* biases — and conflating them is a mistake.

- **At origination, tag liberally.** A writer creating or editing a doc should apply **every domain that plausibly applies** — optimize for recall. It cannot see whether a domain pulls its weight across the whole store, so it should not try to; guessing conservatively just hides a real concern. Over-tagging at birth is expected and harmless.
- **At gardening, prune authoritatively.** Gardening has the whole vocabulary in view, so it is where the finite-shared-resource discipline ([[20260624185845]]) is enforced: it eagerly consolidates synonyms, removes tags that don't justify themselves, and normalizes convention. Pruning is gardening's standing, not the author's.

The one bias both share: **prefer reusing an existing domain over coining a new synonym.** Liberal tagging means *more domains applied per doc*, not *more new domain strings invented* — reuse still curbs drift at the source.

## Consequences

- The registry (`ldoc domains`) is the shared surface both the tag-time writer and the gardening refiner read to see the live vocabulary.
- A newly created doc can carry domains from birth, drawn preferentially from existing ones — so the vocabulary converges instead of fragmenting.
- The reuse nudge is a *bias*, not a hard constraint: a genuinely new concern still earns a new domain. The justify-its-existence discipline decides whether that new domain survives gardening.
