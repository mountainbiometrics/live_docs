## Decision

Wiki-link rendering is **unified** through a single client-side resolver, fed by the export-provided `id -> {label, summary, ...}` map:

- `[[id]]` always renders the referenced doc's **label** — never a raw id — with a **hover tooltip** showing that doc's summary.
- `![[id]]` **transcludes** the referenced doc's body inline.

Because every surface — the doc body, relationship panels, index composition, and tooltips — runs the same resolver against the same map, a reference resolves **identically everywhere**.

## Rationale

One resolver is the mechanism that delivers the consistency a purpose-built viewer promises and Obsidian could not. There is no per-surface link logic to drift: labels, tooltips, and transclusions are all just the resolver applied in different render contexts. The map travels inside the pure-data export, so a consumer never has to re-read the store to resolve a link.
