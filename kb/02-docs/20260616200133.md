## Context

Docs reference other docs via edge fields and body prose. Human-facing porcelain output shows typed wiki-links; body authoring and validate hygiene are separate concerns from that display format.

## Decision

### Human-facing output (porcelain read path)

Any doc reference rendered to a human is formatted as a **typed wiki-link**:

```
[<Intent> <type>: <Title>](<id>.md)
```

- The link text is the doc's line ([[20261006190950]]): its intent, its type, and its title, followed by its force and realization tags where its type carries them.
- `<Title>` is the full doc title.
- `<id>.md` is the canonical filename, giving a navigable link in any markdown viewer.
- The format is readable raw (type and title are human-legible), carries the id for programmatic navigation, and makes the intent and type always present so a bare label is never ambiguous.

Whether the link text uses the full **Title** or the shorter **label** is left to the label convention (see label-and-title). The current rendering uses Title; a future revision may substitute the label when it is sufficiently descriptive and more compact.

### Body prose authoring (stored markdown)

Authors write doc cross-references in bodies as **bare id wikilinks only**: `[[<id>]]`. The porcelain expands these to typed links at read time.

Malformed body wikilink syntax is invalid authoring:

- `[[<id>|<label>]]` — pipe alias form
- `[[<id>]] (<label>)` — parenthetical label after the link

`validate` warns on malformed forms. Bodies must use bare `[[id]]`.

### Prose vs edge consistency (validate only)

`validate` warns when a body contains a `[[id]]` wikilink whose id is **not present in any edge field** (`requires`, `belongs_to`, `relates`, `provenance`, `superseded_by`). This is report-only — validate does not auto-add edges.

## Consequences

- No reference shown to a human is a bare id or a bare label without type context.
- Agents and humans can immediately tell what kind of doc is being referenced, and whether the person asked for it, without an extra call.
- JSON output remains id-keyed for machine consumers and carries the facets as fields ([[20261006190950]]).
- Review snapshots render their entries with the same doc line.
