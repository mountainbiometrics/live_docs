## Decision

Sharding is implemented entirely in the **raw tier**, below the graph. Each child raw clipping carries:

- A **`parent_raw` pointer** to the parent clipping it was carved from. This is a **raw-tier pointer, NOT a graph edge** — raw files are not graph nodes, so this is a path reference recorded in raw frontmatter, not a `requires`/`provenance`/`relates` edge. (Contrast: graph `provenance` edges may *point at* a raw id, but the `parent_raw` link between two raws lives wholly in the raw tier.)
- The **parent's provenance, inherited unchanged.** A child's source lineage is exactly the parent's; sharding is a mechanical division, not a new derivation, so no provenance is added or altered.

## Parent state

The **parent raw remains the immutable whole-archive** — it is never edited or deleted by sharding; it stays the verbatim record of the original. Its **ingest-state is derived**, not set directly:

- `[sharding]` while any child is still pending,
- `[sharded]` once all children have been ingested.

A `[sharding]`/`[sharded]` parent never appears in `ldoc raw list --pending` and is never a direct drain target — draining its leaf children resolves it automatically.

This realizes the **shard-clipping pre-pass** that `[[20260623162457]]` (Pipeline Provenance Metadata) recorded as a then-deferred extension, and uses the same raw-tier provenance machinery. It is a raw-tier consequence of the shard-clipping stage (`[[20260623175228]]`).
