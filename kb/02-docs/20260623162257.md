The live_docs capture→ingest pipeline gains optional provenance metadata so heterogeneous source material (Notion pages, files from different codebases, PDFs, scans) carries enough origin and age context for downstream staleness reasoning. Three new optional fields — origin (the corpus/system, distinguishing both medium and instance, e.g. codebase:foo vs codebase:bar), medium (the source medium: pdf, scan, notion-page, source-file, transcript), and authored_at (when the source was written, allowed to be fuzzy like 2024-03 or circa 2023) — are captured as early as gate 0 (ldoc inbox add) and carried losslessly through gate 1 (ldoc promote) onto the raw clipping.

The governing rationale: three timestamps now have distinct meanings — authored_at (source written) vs. captured (inbox drop) vs. imported (promotion to raw). Previously only imported survived to raw; captured was silently dropped at promotion, and authored_at had nowhere to live. Mixing 2-year-old docs with 2-week-old docs requires authored_at.

A latent inconsistency is also fixed: the raw clipping status was written as the non-enum value 'historical' in some code paths (ingest_raw.py, promote) and 'reference' in others (kb.py); standardized to the valid enum value 'reference'.

Three follow-on items are recorded as planned/target, not done: (a) stamp provenance onto the normalized reference doc too, so extracted atomic docs reach source-age via their provenance edge (requires extending REFERENCE_EXTRA_FIELDS and ldoc new); (b) add ingest-state (pending/ingested) to raw items plus a 'raw list --pending' view for batch backlog processing; (c) a shard-clipping gate-1.5 pre-pass that splits oversized clippings along concept seams before ingest.
