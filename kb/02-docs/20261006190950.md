## Decision

Every surface that lists docs — `ls`, `find`, `map` including children, `neighbors`, `graph`, `log`, review snapshots, `hierarchy.md`, and the MCP tools — renders each doc's line as `<Intent> <type>: <Title>`, followed by the doc's force and realization as trailing tags where its type carries them. For example: "Requested decision: …", "Incidental component: …".

- A doc with no `intent` ([[20261006190938]]) reads "Unattributed".
- A deprecated doc's line is struck through and names its successor.
- Reference docs stay omitted wherever surfaces demote them ([[20260717210152]]) and rank last elsewhere.
- JSON output carries the same facets as fields on each doc entry.
- `intent_basis` and `imposed_by` appear in `get` and `show` only.

The force ([[20261006190941]]) and realization ([[20261006190943]]) tags are the only other facets on the line. The typed wiki-link a porcelain renders for a doc reference uses this line as its link text ([[20260616200133]]).

## Why

Each doc's standing shows on its own line, almost as part of the title ([[20261006190935]]). Leading with the intent makes "Incidental decision" read differently from "Requested decision" at a glance.
