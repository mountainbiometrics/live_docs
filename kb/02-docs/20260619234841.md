A conceptual reframing of the live_docs model, recorded docs-first ahead of the matching code change. The scope/topology axis is reworked along three linked moves. First, the 'index' doc type is retired: a doc earns the navigational-signpost role structurally, by having descendants (incoming belongs_to edges), so any type — component, requirement, principle, decision — can play it. Second, the 'scope' field is redefined from a static portability tag into a topology-derived facet: a doc's effective scope is the union of scope values along its entire belongs_to genealogy, including its own; anchor docs (structural components) set a scope value and descendants inherit, so moving a doc legitimately re-scopes it. Third, the belongs_to/requires distinction is made first-class: belongs_to is the family-tree edge that defines scope, while requires is a dependency that does not pull the depender into the dependency's lineage — effective scope is computed over belongs_to only. Consequentially the former index docs are re-typed (the root becomes the 'The live_docs system' component anchoring the root scope; each structural grouping becomes a scope-anchoring component; Foundational Principles becomes a foundational requirement), summarize-descendants is generalized to any descendant-bearing doc as a variation of cascade-checking, and the viewer's entry-point detection plus the orphan definition must move from type:index to a structural/hierarchy basis. The domain field is untouched.
