## Principle

When a reference must work across machines, commit only the **stable identifier** and resolve the **machine-specific location** separately, per user. The identifier is the same everywhere, so it is safe to check into git; the location differs per machine — a directory on one, the url of a host on another — so it belongs in per-user config, not the shared repo.

## Why

Baking a location into a committed file forces every machine into one filesystem layout. Splitting identifier from location lets a shared reference stay portable while each environment binds it to wherever the target actually lives. This is well-worn prior art — git remotes (`origin` → a local URL), AWS named profiles, kubeconfig contexts, SSH `Host` aliases — which is strong evidence the split is the right shape rather than a novel risk.
