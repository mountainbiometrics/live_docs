## What it is

The MCP endpoint is a surface over the store's shared code ([[20260615185417]]) that answers Model Context Protocol requests over a network. It serves the stores registered on the host it runs on, under the names the registry binds ([[20260703002416]]); a request names the store it is asking about when the host serves more than one.

## The surface is the read porcelain

The endpoint's tools are the porcelain's read commands. Each tool carries a command's name, its arguments, and its semantics, and answers with the same data that command's machine-readable output carries. An agent that orients with `ldoc map`, searches with `ldoc find`, and reads with `ldoc show` knows this surface ([[20260624225629]]). The endpoint exposes the read commands alone, so the porcelain remains the single path a change travels ([[20260618214152]]).

Projecting the porcelain rather than offering an API of its own is what keeps one command surface for agents and skills to learn: a change to a read command reaches the CLI and the endpoint at once.

## What it serves

The endpoint serves the files of a checkout on its host and holds no copy of its own ([[20260615230652]]). Keeping that checkout current belongs to the deployment, done the way any other checkout is kept current.

## Reaching it

The endpoint answers only requests carrying the shared token it is configured with. This is network hygiene: the token check is an affordance for the deployment's security practices, not an auth system, and the network boundary — who can reach the host at all — is the deployment's.

A request also carries the editing session it works under, which the endpoint hands to the shared code along with the store the request names ([[20260615185417]]).
