live_docs gains a read-only MCP endpoint so that agents working on other machines can read a shared store without pulling a checkout of it. The existing store logic becomes the kernel: one library that both front-ends — the CLI and the MCP server — reach down into, with neither front-end calling the other and the server never shelling out to the CLI. Both front-ends are written in Python because the kernel is; the server is the only package allowed non-stdlib dependencies (the official MCP SDK), so the kernel and the CLI stay stdlib-only and `ldoc` keeps working with no server installed. The MCP surface is a projection of the read porcelain — the same command names, arguments, and semantics agents already learn from the CLI — and carries no mutators.

The server serves the stores registered on its host and reads each one from a filesystem checkout, which stays the canonical form of the store; it reloads when those files change. A registry entry's location may be a url instead of a local root; a url-located store is read-only from the client that resolves it, and a mutation against it fails loud. Access to the endpoint is controlled by a shared bearer token, with the network boundary left to the deployment. Agents on many machines writing into one shared store is a stated need that this read path does not serve.

Serving the store this way is packaging, not a change of identity: live_docs remains a write-time discipline system, harness-agnostic, and ships a thin read-only projection of its read porcelain the way it ships skills for Claude Code.

The settled design this restates — the code and store survey it rests on, and the four decisions the owner ratified on it — is archived at `raw/20260916170849.md`.
