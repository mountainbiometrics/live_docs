## Statement

live_docs exists to capture the **nonrecoverable why-web**: the principles, constraints, requirements, and goals that justified choices — and the decision process that weighed them. It does **not** exist to restate the **what** — the structure and behavior the code already encodes — nor to replicate ordinary design or ADR documents.

## Rationale

The *what* is recoverable from the code at any moment. **Decisions themselves are often recoverable** too — from code shape, commit history, and design docs. What is not recoverable once the conversation ends are the driving reasons: the constraints that bounded the options, the goals and requirements that had to be satisfied, the principles that ruled options out. That why-web is what live_docs must hold as first-class docs.

A discovery, ingest, or reconcile pass that recreates the *what* from the *why* has **failed**: it has merely transcribed the code into prose, producing many implementation-detail docs and almost no durable knowledge. The same failure, one step subtler: a pile of docs that restate outcomes ("the answer engine lives in the hub") without the why that placement was chosen. Prefer docs that explain *why* the choice was made; keep `decision` docs **thin** modeling nodes that **`require`** the why-web roots they rest on.

live_docs is a **higher-resolution lens into the why**, not a replacement for ordinary design documentation. The test for every doc is whether it would still be true and useful after the implementation it describes was rewritten — and whether, when the decision is later challenged, a reader can find the requirements, constraints, and goals that must still be considered ([[20260707170659]]).

This extends to the *current state itself*. When something was built and later removed, the artifact and the git history show *that* it changed — but only a why-doc records *why the current state is what it is*. Without it, a future reader sees the residue of a decision with no way to tell whether the current shape is deliberate or accidental.

The directional consequence — that the docs *lead* and the code aligns to them, not the reverse — is its own architectural decision: [[20260707164539]].
