A second-generation redesign of the editing-session subsystem, settled through grilling against the KB. Sessions become on-disk, first-class, and mandatory: a mutation with no open session auto-creates one (announcing it), the session id still propagates ambiently through LDOC_SESSION (the id pointer specifically cannot be a shared persisted file, since concurrent sessions would conflate it), and setting LDOC_SESSION when one is already set is an error. Each open session keeps an on-disk record holding a settable agent-recap summary and a write-ahead change log (WAL); every mutation double-writes — a per-doc history entry and a WAL line — and the WAL is the source of truth for the session's review, being the only place deletions are recorded. Each history/WAL entry carries a change_type set by which command ran: addition (new), revision (body/label/title/summary), restructure (requires/belongs_to/status/level/type/scope/superseded_by), organizational (relates/provenance/domain/keywords), deletion (rm). The WAL records the full list of types touched; review rollup files each doc once under a single dominant type by precedence deletion > revision > restructure > organizational. Review sections become Additions / Revisions / Restructure / Organizational / Deletions. Creation is now recorded as a session-tagged addition history entry, which supersedes the old rule that history excludes creation and lets the redundant `created` field be dropped (creation time = the addition entry's timestamp); existing docs are migrated by a one-shot `ldoc migrate`, reads tolerate a lingering `created` and stay pure, and a doc heals on its next write. Change explanations move inline: `--note` on the mutating command replaces the deprecated standalone `ldoc history` (retained only as a post-hoc gap-filler); obvious commands auto-fill the note, and a revision-class change requires an author-supplied note — missing notes only nag per-command but block `session close` until every revision-touched doc carries one. Closing a session rolls its WAL up into exactly one review (archived losslessly into a non-rendered block of the review file) and deletes the live session record. Sessions can be listed with their age and note-coverage, resumed (by re-exporting the id), and merged (fragments folded into the earliest, re-tagged, WALs concatenated). addition entries are excluded from the hot-file churn signal.
