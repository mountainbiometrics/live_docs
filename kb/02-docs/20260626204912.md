## Decision

Dangling **outbound** edge detection — an edge field pointing at a doc id that does not exist — is implemented once and shared by:

- `ldoc edges` (diagnostic report)
- `ldoc validate` (structural integrity pass)

The unified detector covers all **blocking** edge types: `requires`, `belongs_to`, `relates`, and `superseded_by`. `provenance` refs that do not resolve remain a **WARNING** only (unchanged).

There is **no** `ldoc gc-edges` verb. Dangling edges are cleaned up explicitly (`ldoc unlink` on the source doc, including literal dead 14-digit ids) or indirectly when `ldoc rm --force` strips inbound edges before deletion.

## Rationale

Split implementations drift: `edges.py` and `validate` previously disagreed on which edge types to scan. One shared helper keeps the porcelain honest — agents see the same dangling set whether they run `ldoc edges` or `ldoc validate`.
