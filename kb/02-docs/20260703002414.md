## Requirement

A consumer repo's store reference — the `store` value in its `.live_docs.toml` — is committed to git, so it **must resolve to the same store for every teammate** who clones that repo, not to whatever each developer happened to name it locally.

## Why

The point of a shared store is that many repos and many developers converge on one knowledge base. If the reference were a per-user alias, a committed `store = "acme-docs"` would only work for teammates who happened to pick the same alias. Requiring the reference to be team-portable is what forces the store to own its canonical name rather than leaving naming to each consumer.
