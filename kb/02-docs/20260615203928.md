## Context

idea_dump described timestamps and audit trail as serving a secondary purpose beyond change provenance: 'Can be used to track "hot" vs stable files (number of edits)' and explicitly flagged 'related skills: hot files are candidates for breaking down into a set of more atomic documents.' The `history:` frontmatter list records every change; its length is therefore a measurable signal of churn.

## Decision

A doc with an unusually long `history:` list is a 'hot file' and a first-class candidate for the garden skill's decomposition pass. The garden skill should surface hot files — those with history length above a threshold (e.g. 5 entries) — as a decomposition smell, alongside the existing two-reasons-to-change smell. History length is the only churn signal tracked by live_docs itself; external signals (git commit count) are optional layering.

## Consequences

- garden skill should include a hot-file detector as part of its standard smell inventory.
- The threshold (5 entries) is a starting heuristic; it can be tuned or made configurable.
- Hot-file detection applies only to `living` docs. A `historical` doc with many history entries is expected (it recorded its evolution before archiving).
