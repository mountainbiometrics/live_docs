## Decision

A store **self-registers** when `ldoc` runs inside it: `ldoc` reads the store's own declared `name` and binds it to the store's current root. This is argument-free and **idempotent** — a no-op when the name is already bound to that same path. It **never overwrites**: if the name is already bound to a *different* path, the auto-registration fails loudly (on stderr) but does **not** block the `ldoc` command you actually ran — standing inside a store, you do not need the registry to use it. `ldoc store register [path]` does the same explicitly; **`--force`** is the only way to repoint an existing binding. `ldoc store list` and `ldoc store forget <name>` manage the registry.

## Rationale

Self-registration folds into existing onboarding with no extra step and self-heals a moved checkout (the next in-store command re-binds under `--force`). Refusing to overwrite — rather than upserting — is what enforces the no-silent-rebinding constraint: the automatic path never hijacks a name; only a human, with `--force`, repoints one deliberately.
