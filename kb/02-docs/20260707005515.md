## Statement

A living doc is kept current by **regenerating it** — not by leaving a flag for later, and not by patching a sentence around the change. When a dependency moves, cascade repairs each stale dependent by **rewriting that single atomic doc to current truth from the graph**: a surgical regeneration bounded to the affected node, never a wholesale rebuild and never a snapshot left to rot.

## Rationale

Two failure modes bracket the right behavior. Regenerating the *whole* corpus from the code throws away the why — every rebuild is lossy because the only input is the artifact. At the other extreme, merely *flagging* a dependent as "possibly stale," or minimally patching one line, leaves the doc drifting under a warning label. Neither keeps the doc **living**.

The correct repair is surgical regeneration **from the graph**: the dependent is re-derived from its own dependencies' current state — which still carries the intent — so the rewrite stays faithful, and the blast radius is exactly the atomic node(s) the `cascade` verdict named. This is only *safe* because docs are atomic with explicit edges ([[20260625222626]]): a single-responsibility doc with a known dependency boundary can be rewritten whole without endangering anything else. In a monolith, regeneration would be all-or-nothing; atomicity is what makes it local.

"Living, not snapshotted" is the crux. A snapshot is dead the moment it is taken and drifts from then on. A living doc is one that is **re-derived when its inputs change**, so it stays current relative to what it depends on. Cascade ([[20260615100012]]) is the mechanism that keeps docs living rather than snapshotting them — the `cascade` verdict is an instruction to regenerate, not merely to note. This is the operational face of living-over-stale ([[20260615100001]]): the standard is what the doc *should* now say, so an actor that under-regenerates — flagging where it should rewrite — is the side that must change, not the doc.
