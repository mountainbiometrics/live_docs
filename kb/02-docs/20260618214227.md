## Use-case

The long-term **target deployment** is a single live_docs store holding the design docs for **many separate code repositories**.

## Consumer markers

Each attached code repo carries a **consumer marker** — a one-line `.live_docs.toml` whose `store` key points at the shared store (`[[20260702205002]]`). That repo is not a live_docs store; it reads and writes the shared KB under `STORE_ROOT` (`[[20260702205006]]`) while `CONSUMER_ROOT` remains the code checkout.

## The force it creates

In a multi-repo deployment the store's tooling does not scan the other repos, so it cannot observe on its own whether a documented intention has been implemented. Each realizable doc therefore records its own `realization`, with anchors into whichever repo implements it and a stamp saying when that was last checked ([[20261006190943]], [[20261006190944]]). The realization sync ([[20261006190952]]) refreshes them scope by scope, run by an agent where the implementation lives.

## Why it matters now

The use-case is **invisible in the current self-hosting instance**, where code and docs share one tree and a transition can sometimes be eyeballed. But it defines the **hardest constraints** on the system, so the design is shaped by it even before any external repo is attached.
