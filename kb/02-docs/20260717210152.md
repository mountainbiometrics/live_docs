## Decision

Across every store interface (CLI, viewer, and future surfaces), docs with **`type: reference`** or **`status: reference`** are demoted relative to current claims:

1. **Orientation and listing defaults omit them** — including `ldoc map`, default `ldoc ls`/orphan/entry-point derivation, viewer hierarchy tree, neighborhood graph, and catalog-default listings. Docs with `status: target` remain in these surfaces; demotion is about reference/archived material, not the living-vs-target adoption axis.
2. **Search deprioritizes them** — `ldoc find` (and equivalent search) ranks non-reference matches first and groups reference/archived hits last.
3. **Default validate skips them** — structural checks run on the non-reference corpus. `--include-reference` opts into checking reference/archived docs too. That flag is opt-in specifically because archive-link hygiene is **not** a requirement for a healthy current model; agents must not treat reference/raw dangling noise as blocking lint.
4. **Reachability is preserved** — reference docs remain in exports for link resolution and still appear in per-doc connection lists when something cites them.

## Why

Reference docs are frozen snapshots for citation. When they compete in `map`, validate, or search, agents learn to treat archive material as the system. Demotion keeps interfaces about current claims while leaving footnotes followable. CLI orientation is especially load-bearing: what `ldoc map` and default validate surface is what agents explore and "fix."
