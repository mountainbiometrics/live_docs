## Decision

The Reader **hierarchy sidebar** must make nesting discernible at a glance and stay stable while moving between docs:

- **Visual nesting** — nested signposts use minimal per-level indent (nested containers, not large padding), vertical guide lines, disclosure carets, and child-count badges on folders. A reader can see depth and siblinghood without collapsing sections to compare what appears or disappears.
- **Stateful tree** — the sidebar is built once; navigating between docs updates only the content pane and active highlight. Manual expand/collapse and scroll position persist. Jumping to a doc via a link opens its `belongs_to` ancestor path so the active row is visible without resetting unrelated branches. Active signpost summaries are highlighted, not only leaves.
- **Bulk expand/collapse** — toolbar actions **Expand all** and **Collapse all** set every folder open or closed. **Default on load**: top-level signposts (and Ungrouped) expanded; nested folders collapsed.

## Rationale

Curated stores are often four or more levels deep; heavy per-level padding consumes the narrow sidebar. Minimal indent plus guide lines trade pixels for legibility. Rebuilding the tree on every navigation destroyed manual tree state and made hierarchy browsing painful.
