How external material and session decisions enter the store: the async inbox, the batch ingest pass, and the docs-first/reconcile/apply workflows that materialize intent into atomic docs.

The framing principle is `[[20260615100016]]` (Ingest Gardening Core): ingest and gardening are foundational passes, not deferred features. The capture path runs through `[[20260616181805]]` (Async Inbox), which decouples capture from ingestion, and `[[20260616181832]]` (Inbox Pipeline), the drop-point plus batch ingest pass that drains it. The intent-first workflows are anchored by `[[20260616181843]]` (Plan Changes Docs-First) — record intent in docs before building so the store leads reality — and realized by `[[20260618000147]]` (Apply-to-docs Skill), the skill that materializes a request or plan into the store, with `[[20260618000209]]` (Apply-to-docs Must Pause) requiring it to pause and warn when the blast radius is large. The governing rule across all of it is `[[20260618000251]]` (Understand Before Write): survey for compatible, conflicting, or superseded claims before any write. `[[20260618213505]]` (Reconcile Changes) handles the reverse direction — catching the store up to changes already made, recording them as living docs.
