## Decision

Optional **`[viewer] build_path`** in the store's `.live_docs.toml` sets the file path of the generated HTML viewer artifact. When omitted, the default is **`build/viewer.html`**.

Resolution rules:

- Relative paths resolve against **`STORE_ROOT`**.
- Absolute paths, `~` expansion that leaves the store, and any resolved path outside `STORE_ROOT` are **errors** (fail loud) — the porcelain does not silently reinterpret them as store-relative.
- Outside-store publishing remains available via symlink or copy; config never writes outside the store.

Who honors it:

- **`ldoc viewer`** and **porcelain auto-rebuild** both write to the configured path.
- CLI **`--out PATH`** overrides for a one-shot build only; it does not change the configured default.

The key lives on the same **`[viewer]`** table as branding keys (`[[20260710235233]]`) — a viewer concern, not a KB box relocation.

## Why

Hardcoding `STORE_ROOT/build/viewer.html` blocked store-local layout choices (e.g. a preferred name or subdirectory) while still keeping artifacts under the store root that owns the KB.
