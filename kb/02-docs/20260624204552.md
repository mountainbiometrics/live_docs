## Context

The Catalog is the viewer's facet mode (`[[20260619204849]]`). Early implementation exposed type, status, level, and a derived scope facet via dropdowns only; domain was exported but not rendered. A follow-on pass added domain columns/filters and scope path display (`[[20260624202025]]`), then refined table UX: column order, in-row click-to-filter, and non-link chip styling.

## Decision

**Column set and order** (left to right): `created`, `label`, `type`, `scope`, `domain`, `level`, `status`. The **title column is omitted** — label is sufficient in tabular facet view (title remains on Reader and tooltips).

**In-row facets are clickable filters.** Clicking a cell chip sets the matching catalog filter and re-renders (dropdowns stay in sync):

| Cell | Filter axis | Match rule |
|------|-------------|------------|
| Type | `type` | exact |
| Status | `status` | exact |
| Level | `level` | exact |
| Scope crumb | `scope` | doc's **effective scope** union includes that anchor |
| Domain pill | `domain` | doc's own `domain` list includes that tag |

**Visual styling:** clickable chips use the same appearance as read-only facets — **not** link color or underlines. Hover is a subtle background only. Scope renders as **breadcrumb segments** (`live_docs / viewer`); domain renders as **colored pills** with consistent padding in the table.

Dropdown filters, group-by (including scope and domain), text search, presets, and column-header sort remain as complementary controls.

## Consequences

- Catalog-specific presentation lives in `scripts/viewer/template.html` under the Catalog section; the pure-data export contract is unchanged.
- Global facet display on non-catalog surfaces is governed separately by `[[20260624202025]]`.
