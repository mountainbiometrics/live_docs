## Context

`scope` began as a static portability tag — `scope: [live_docs]` marked docs that describe the portable system so they could be extracted from MTN-specific knowledge. That use named a *fact about a doc*. The reframing promotes `scope` into the primary **topological facet axis**: it names a zone of the system, and zone membership follows the hierarchy rather than being hand-stamped on every doc.

## Decision

`scope` is a string field that **declares a topological zone/facet**. When set on a doc, its value applies to that doc **and its entire `belongs_to` descendant subtree**.

A doc's **effective scope** is the **union of `scope` values along its whole `belongs_to` genealogy** — the full chain of ancestors, not just the nearest parent — **including its own**. Effective scope is computed over `belongs_to` **only**, never `requires` (see the belongs_to-vs-requires distinction).

Most docs set **no** `scope` and simply inherit. **Anchor docs** — the structural components and subsystems — set a `scope` value: the root component anchors the root scope (`live_docs`), the Viewer component a `viewer` scope, the Review component a `review` scope, and so on. Inheritance plus periodic gardening propagates the facet; leaf docs are not hand-stamped.

## Scope is derived, not materialized

Effective scope is **computed from topology**, not stored per-doc. Moving a doc under a new parent **legitimately re-scopes it** — this is correct and intended, exactly analogous to filtering an object by its path in a tree. It is **not** undesirable coupling: the whole point is that lineage carries facet membership, so a doc's zone is always consistent with where it actually sits.

## Consequences

- This topological `scope` facet powers the viewer's **scope breadcrumbs** and the **Catalog scope-facet**: both read effective scope off the genealogy. Preview surfaces show the anchor chain as a **breadcrumb trail**; Catalog filtering still uses the union. See `[[20260624202025]]` and `[[20260624204552]]`.
- The old portability use of `scope` is **subsumed**: `scope: [live_docs]` is now the root anchor's value inherited by the whole store, rather than a tag repeated on every system-spec doc. The portability decision and the domain-vs-scope contrast are updated accordingly.
- Materializing anchor values on existing component docs requires a porcelain capability to set `scope` on a doc (`ldoc set --scope`), which does not yet exist; that is a deferred code change. The model and the anchor assignments are recorded here ahead of it.
