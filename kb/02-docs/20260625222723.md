## Statement

The distinctive value of gardening — and of examining the codebase through the lens of the living docs — is **evaluative**: the agent judging when something is idiotic, redundant, or no longer earning its place. Cataloguing what exists is the low-value part; deciding what should *stop* existing is the high-value part.

## Rationale

Structural upkeep — re-homing, summarizing, splitting — is necessary but mechanical; a script-like pass can approximate it. The judgment a capable agent brings that no mechanical pass can is **criticism**: spotting the decision that no longer makes sense, the component that was built, outlived its reason, and should be removed, the doc that records a what with no surviving why ([[20260625222638]]).

This is also the lever against the **intention-lost** failure mode. When something was built and then removed, the artifact and git show *that* it changed, but nothing records *why the current state is what it is*. An evaluative pass is what surfaces that gap and forces the choice: recover the intent into a why-doc, or prune the residue. Treating gardening as mere tidying misses exactly this — the most valuable thing the pass can do is conclude that something should not be there at all (and then delete it, per [[20260624224407]]).
