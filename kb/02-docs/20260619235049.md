## Context

The viewer and the validate/reindex tooling both keyed off `type:index`: the viewer built its hierarchy and entry-point list from index docs, and `orphan` was defined as "a doc with no `belongs_to` and `type != index`." With the index type retired, both definitions break and must move to a structural basis.

## Constraint

**Entry points are derived structurally, not by type.** An entry point is a doc that is a **root of a large subtree** — no `belongs_to` ancestors yet many descendants — and/or a **scope-anchoring component**. Surfaces read these off the topology (and the `scope` anchors), not off any `type:index` marker.

**Reference/archived roots are not entry points.** Docs with `type: reference` or `status: reference` are excluded from default entry-point and floating-root lists even when they have no `belongs_to` — demotion is store-wide ([[20260717210152]]). They must not appear as orientation peers to current-claim roots in `ldoc map` or equivalent views.

**The orphan definition becomes hierarchy-based.** An orphan is a doc with no `belongs_to` that is NOT a legitimate top-level component; top-level components (the root and the structural subsystems) are not orphans. Reference/archived docs without a parent are demoted archive material, not hierarchy orphans to "fix" by scoping.
