## Context

The viewer and the validate/reindex tooling both keyed off `type:index`: the viewer built its hierarchy and entry-point list from index docs, and `orphan` was defined as "a doc with no `belongs_to` and `type != index`." With the index type retired, both definitions break and must move to a structural basis.

## Constraint

**Entry points are derived structurally, not by type.** An entry point is a doc that is a **root of a large subtree** — no `belongs_to` ancestors yet many descendants — and/or a **scope-anchoring component**. The viewer reads these off the topology (and the `scope` anchors), not off any `type:index` marker.

**The orphan definition becomes hierarchy-based.** Currently `orphan` means "no `belongs_to` and `type != index`." It must become: **a doc with no `belongs_to` that is NOT a legitimate top-level component is an orphan; top-level components (the root and the structural subsystems) are not orphans.** Legitimacy is structural — a top-level component is an intentional root that anchors a scope, whereas an orphan is a doc that fell out of the hierarchy by accident.

## Status

This is recorded for the **deferred code phase**. The viewer (`build_viewer.py`), `validate`, and `reindex` still encode the `type:index` assumptions; this constraint names what they must become so the docs and code reconverge.
