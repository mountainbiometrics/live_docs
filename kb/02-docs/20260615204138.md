## Context

idea_dump proposed signpost docs as navigation aids and described "skills for grouping docs under a new index/folder (w/ summary)" with "aggregated summaries of all descendants." The concern was that traversing a flat, highly-atomic store requires either loading many docs into context or having a higher-level read that narrows the search before descending.

## Decision

**Any doc with descendants** — incoming `belongs_to` edges — carries a **synthesized orientation overview** of its subtree. The overview makes that doc a true navigational signpost: a reader can grasp what the branch is about, how the pieces fit, and where to start, without opening each child.

It is a **macro read, not a recap**. It does not restate or roll up each child's summary — the viewer already displays child summaries beneath the signpost, so duplicating them in the parent body is redundant. The parent synthesizes the *shape* of the subtree (what it is for, how the pieces relate, where to begin); it does not enumerate the parts.

This is **not tied to a special type**: the `index` type is retired, and the signpost role belongs to whatever descendant-bearing doc occupies the position (a component, a requirement, a principle).

## garden-summarize is a variation of cascade-checking

Orientation overviews are **cascade-sensitive in a specific way**: redefining a child or sub-component within a system can **reframe the parent/system as a whole**. A parent's synthesis therefore depends on its children's current meaning, so the summarizing phase — **garden-summarize** — is best understood as a **variation of cascade-checking**: when a member is substantively edited, the parent's synthesis goes stale and must be re-run. `cascade-check` propagates this stale signal upward through `belongs_to` edges, exactly as it does for any other downstream-dependency invalidation.

## Consequences

- The garden-summarize phase produces and updates these overviews (its mechanics target any descendant-bearing doc, not only the former index type).
- The cognitive-load principle grounds this: a synthesized overview lets a reader navigate by scanning, not by absorbing every doc in a branch.
- Because the trigger is "a member changed," the behavior composes with the normal cascade machinery rather than being a separate special case.
