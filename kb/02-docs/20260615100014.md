## Context

Docs vary in authority. Some derive from explicit user decisions or external sources; others emerged as agent articulations, organic notes, or unconfirmed suggestions. The system needs to distinguish these without inventing a separate provenance-tier enum — schema provenance remains the edge; `level` carries settledness.

## Decision

Every doc should record its source or derivation via a `provenance` edge (or reference `--source`). A doc with **no** recorded provenance is treated as `level: incidental` — not a decided thing, just something that happened to be written down.

That is necessary but **not sufficient** for authority:

- **`level` means claim settledness / authority**, not "has a provenance edge." Archiving a session digest and pointing `provenance` at it does not make every extracted claim a `requirement`.
- **Silence is not ratification** ([[20260723223658]]). An agent-proposed claim the user did not explicitly confirm stays `level: incidental` even when a provenance edge exists. "Didn't contradict" is not "said so."
- **Do not confuse `level: requirement` with `type: requirement`.** The enum value names settledness; the type names the kind of knowledge. Agents that stamp every documented claim `level: requirement` because it "feels like a requirement" erase the incidental signal.

Raise `level` above incidental only when the source evidence for *this claim* supports that settledness (user-stated or clearly confirmed). Gardening can later elevate or delete incidentals.

## Consequences

The decided/emergent distinction becomes self-enforcing through metadata (P3), with a gentle incentive to record provenance — and a hard brake against treating provenance as automatic high authority. Gardening passes can surface `incidental` docs as candidates for elevation or deletion (P2, P6). Agent-facing skills must operationalize this rule; KB recording alone does not reach external agents ([[20260624225658]]).
