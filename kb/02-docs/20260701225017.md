## Decision

A change's explanation is attached **inline**, via `--note` on the mutating command itself, rather than through a separate logging step. This makes the note and the change **atomic** and lets `ldoc` stamp the note with the right change_type automatically.

## ldoc history is demoted

The standalone `ldoc history` verb is **deprecated** as the everyday path — inline `--note` supplants it. It is **retained** only as a post-hoc **gap-filler**: the tool you reach for when `session close` reports that a doc's meaningful change went unexplained.

## Auto-filled vs author-supplied

**Obvious** changes auto-fill their note — `new` -> "Created doc", a re-parent -> "Reparented from X to Y", an unlink -> "Removed <edge> to X", `rm` -> "Deleted <label>". **Non-obvious** changes — a rewritten body or summary — carry no meaningful auto-text and must be explained by their author, enforced at session close.
