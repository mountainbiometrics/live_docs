## Decision

Navigation has **three orthogonal modes**, each answering a different question:

- **Hierarchy** — a sidebar tree built from **`belongs_to`**, rooted at the descendant-bearing structural components (no longer keyed off a `type:index` marker, which is retired). Answers "where does this sit in the curated structure?" Presentation details: `[[20260623215558]]` (nesting visualization, stateful tree, expand/collapse defaults) and `[[20260623215600]]` (default type-then-label ordering within sibling lists).
- **Facet** — `[[20260624204545]]` (Catalog View): a filterable, groupable table over frontmatter fields. Answers "show me all docs matching these attributes." Table layout, columns, and click-to-filter: `[[20260624204552]]`. Scope and domain facet display on other surfaces: `[[20260624202025]]`. Default row order follows `[[20260623215600]]`; column-header sort overrides.
- **Graph** — a local **2-hop neighborhood** around a focused doc, with **per-edge-type force tuning** so different edge types lay out distinctly. Answers "what is this doc connected to?"

## Priority

**Hierarchy and facet are the primary daily drivers.** The **graph view is additive and deferred** — valuable for exploration but not required for the viewer to be useful day to day.
