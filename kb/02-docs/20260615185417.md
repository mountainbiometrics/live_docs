## Context

Skills initially carried their own Python implementation files; ad-hoc verification scripts re-derived the same parsing and edge-building logic in each tool independently.

## Decision

All tooling logic lives in `scripts/` — a shared `livedocs.py` module (frontmatter parser, graph helpers) plus single-responsibility CLIs (`validate.py`, `reindex.py`, `edges.py`). Skill directories hold thin bash wrappers that resolve the repo root from their own location and exec the corresponding script. Verification and cascade-check call the shared scripts rather than hand-rolling their own python.

## Consequences

- One place to maintain parsing and edge logic; every tool benefits from fixes automatically.
- Skills stay declarative (SKILL.md describes intent; the bash wrapper is a one-liner).
- Single-responsibility applied to tooling as well as to docs.
- `edges.py --json` is the canonical source for fresh forward/reverse maps; no tool re-derives them.
