## Decision

A store `.live_docs.toml` may set a **`base`** key naming the KB parent directory. When `base` is set, any omitted box key resolves to its slot in the **canonical layout** beneath `base` — the layout defined and owned by `[[20260618214315]]` (Numbered KB Boxes) and the decisions that introduce each sibling box. `base` does not redefine that layout; it only supplies the parent directory the layout hangs under.

Explicit per-box keys still override the `base` defaults. Paths resolve relative to the config file that defines them (absolute and `~` honored).

## Rationale

Most stores colocate all boxes under one `kb/` parent. Spelling out a path line per box in every config restates the layout convention that other decisions already own — inviting the two definitions to drift apart. A single `base` line captures the common case, defers the box names to their owners, and still allows relocating any individual box.
