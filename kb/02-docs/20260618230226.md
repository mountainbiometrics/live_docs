The physical and organizational layout of the store: box staging under kb/, configurable paths, flat domain/scope fields, opaque IDs, and how the root index is structured.

Content is staged by `[[20260618214315]]` (Numbered KB Boxes), which lays material out in numbered boxes under kb/ by distillation stage, with `[[20260618214257]]` (Configurable Boxes) keeping those box paths in config so scripts read them and skills stay path-agnostic. Identity and grouping fields: `[[20260615100010]]` (Opaque IDs) makes filenames opaque timestamp IDs with the human-readable title in frontmatter; `[[20260615203839]]` (Domain Tag) and `[[20260618214306]]` (Flat Domain Scope) define domain and scope as flat top-level fields over an open vocabulary, not nested under tags. The index machinery is covered by `[[20260615204138]]` (Index Summaries), where index docs carry aggregated summaries of their descendants, and `[[20260618214324]]` (Root Index Stub), which keeps the root index a stub with no per-type definition docs.
