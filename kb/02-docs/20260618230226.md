The physical and organizational layout of the store: box staging, configurable paths, identity and grouping fields, the audit trail, the portability boundary, and the root structure.

Content is staged by `[[20260618214315]]` (Numbered KB Boxes), which lays material out in numbered boxes under kb/ by distillation stage, with `[[20260618214257]]` (Configurable Boxes) keeping those box paths in config so scripts read them and skills stay path-agnostic. Three further decisions carry that configuration across repositories: `[[20260702205000]]` (Config Base Key) collapses the box paths to a single `base` parent; `[[20260702205002]]` (Store Delegation) lets a code repo carry a one-line marker that points at a shared store via `store` instead of being a store itself; and `[[20260702205006]]` (Store Root Terminology) separates `STORE_ROOT` (where the KB and its artifacts live) from `CONSUMER_ROOT` (the code repo), so generated output never sprawls into consumers. A **named-stores** layer builds on these — `[[20260703002416]]` (Named Stores) lets a consumer reference a shared store by a portable name the store declares, resolved through a per-user registry, with fail-loud registration that never silently rebinds a name. Identity and grouping fields: `[[20260615100010]]` (Opaque IDs) makes filenames opaque timestamp IDs with the human-readable title in frontmatter; `[[20260615203839]]` (Domain Tag) and `[[20260618214306]]` (Flat Domain Scope) define domain and scope as flat top-level fields over an open vocabulary, not nested under tags. Alongside those sits a third flat, non-inherited tag field for a different purpose: `[[20260623233935]]` (Keywords Findability) defines `keywords`, an ungoverned bag of search synonyms that makes a doc findable — distinct from `domain` (a governed business-grouping facet) and from `scope` (the topological-zone axis). The signpost machinery is covered by `[[20260615204138]]` (Descendant Summaries), where each descendant-bearing doc carries a synthesized orientation overview of its subtree — a macro read of what the branch is about, not a recap of each child's summary — and `[[20260618214324]]` (Root Component), which makes the root a structural component rather than a hand-written catalog.

Three decisions govern the audit trail and portability boundary. `[[20260615100008]]` (Git Optional Audit) places the authoritative audit trail inside frontmatter itself — each doc carries a history list of timestamped, plain-language entries — with git as optional layering on top. `[[20260615100017]]` (Portable System vs Instance) draws the portability line: live_docs is the portable system; a store that consumes it is a specific instance. System-specification docs live under the root scope anchor and inherit it through belongs_to lineage, so they can be extracted without taking instance-specific knowledge with them. `[[20260615182358]]` (Knowledge Not Impl) sets the scope of what the store captures: knowledge about an implementation, not governance of the implementation itself — skills and scripts are code, not graph nodes, and code-to-knowledge sync remains deferred to the panel layer.
