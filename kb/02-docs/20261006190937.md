## Statement

All tooling over the store is loose on input and strict on output.

- **Reading.** A field the tool does not know is preserved and otherwise ignored. A field the tool expects but does not find produces a warning. Reads, listings, and validation keep functioning either way.
- **Writing.** The tool refuses to write a doc that violates the schema, such as a doc missing a facet its type requires, and fails loud with the instruction to fix it.

## Why

Everything should keep functioning when a store carries fields the tooling does not expect, or lacks fields it does expect: a warning names the gap without blocking work. That keeps a store usable while it moves to a new structure ([[20261006190928]]). Strict output means the tooling itself never adds to the gap.
