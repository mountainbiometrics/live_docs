## Decision

The viewer is delivered as a **single self-contained HTML file** with all docs inlined as a JS array (the pure-data export). It runs directly from `file://` with **no server and no network access**, which makes it portable, archivable, and trivially shareable — one file is the whole reader plus a frozen snapshot of the store.

## Build-artifact status

The generated HTML is a **build artifact, not committed**, written to **`STORE_ROOT/build/viewer.html`** (`[[20260702205006]]`). When a code repo delegates via `store`, `STORE_ROOT` is the shared store — the viewer is **not** written into the consumer checkout. `docs/` remains the single source of truth; the viewer is regenerated from it **on demand** (`ldoc viewer`) and **automatically after porcelain mutations** to docs/ or reviews/ (see `[[20260623191806]]`). This mirrors `git instaweb`: the browsable output is generated from the repository and is never checked in.

## Rationale

A self-contained `file://` artifact has no runtime dependencies, so it survives being emailed, archived, or opened years later with nothing installed. Anchoring build output to `STORE_ROOT` keeps one artifact location for multi-repo deployments and prevents stray `build/` directories across consumer repos.
