## Decision

The viewer is delivered as a **single self-contained HTML file** with all docs inlined as a JS array (the pure-data export). It runs directly from `file://` with **no server and no network access**, which makes it portable, archivable, and trivially shareable — one file is the whole reader plus a frozen snapshot of the store.

## Build-artifact status

The generated HTML is a **build artifact, not committed**. `docs/` remains the single source of truth; the viewer is regenerated from it **on demand** (`ldoc viewer`) and **automatically after porcelain mutations** to docs/ or reviews/ (see `[[20260623191806]]`). This mirrors `git instaweb`: the browsable output is generated from the repository and is never checked in.

## Rationale

A self-contained `file://` artifact has no runtime dependencies, so it survives being emailed, archived, or opened years later with nothing installed. Treating it as derived output keeps the store authoritative and avoids committing a redundant, churning copy of the data.
