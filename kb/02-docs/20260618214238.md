## Use-case

A person and an agent make decisions and implement them in a **working session**, so reality moves ahead of the docs. The decisions are already **living truth** — just unrecorded.

## What the store must do

Catch up to reality, capturing **especially the nonrecoverable why-web** (principles, goals, requirements, constraints that justified choices — with decisions kept thin and wired to those roots), **without treating the changes as proposals**. There is no pre-implementation pause and no re-approval, because the change already happened — we record reality, not a plan. Recreating the what from the why has failed.

## Boundaries

This use-case is served by the **reconcile-changes** process and skill. It is distinct from:

- **apply-to-docs**, which deliberately pauses before writing because there the change is still a *proposal*;
- **ingest-reference**, whose source is *external* material (meeting notes, RFCs, articles), not our own decisions.

The session digest that anchors the docs derived from it is the **first run** of this use-case.
