## Decision

Wherever the viewer names a doc for a human, it may also show the doc's **opaque id** as a small, secondary badge — tooltips, reader meta line, hierarchy tree, review cards, and similar surfaces. The badge is deliberately non-prominent: the label/title remains the primary signal.

## Why

Agents almost always reference docs by id. Humans reviewing agent work (and signing reviews) need those ids visible without turning every surface into an id-first UI. A secondary badge bridges the two audiences on the same read-only projection.
