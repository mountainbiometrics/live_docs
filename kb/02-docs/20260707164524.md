## Constraint

Coding-agent harnesses and the retrieval machinery around them — a particular agent framework, a RAG index, an MCP server, a prompt-assembly scheme — are **heterogeneous, fast-moving, and not ours to own**. live_docs couples to none of them. They are downstream, swappable layers that *read* the store; the store neither assumes nor ships any one of them.

## Rationale

This follows from what the system does ([[20260707005524]]): its job is keeping intent-bearing knowledge true as reality changes, a write-time concern, while retrieval and harness integration are read-time layers over an already-true store. Because the value is in the store being *true* rather than in how bytes reach an agent, the harness can be chosen per consumer and swapped without touching the core.

So being **unopinionated about the harness is a consequence of that boundary, not a gap**. It is the same shape as tool-agnosticism ([[20260615100000]]) for how docs are authored, and the knowledge-not-implementation boundary ([[20260615182358]]) for what the store governs: live_docs defines and maintains the knowledge; it does not own the pipe that serves it, nor the agent that consumes it.
