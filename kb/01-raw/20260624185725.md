Domain tag model redesign from design discussion. Key points:

1. A domain's trigger is self-justification, not a scope-count. The '≥2 scopes' heuristic is REJECTED as the trigger for whether a domain should exist. A domain earns existence by pulling its own weight as a distinct grouping a reader would filter by.

2. The domain vocabulary is a finite shared resource, curated qualitatively not by volume. How many domains should exist depends entirely on the size/complexity of the documented system — no volume rules or target counts. Each domain must hold water / pull its weight. Near-synonyms (acct_management vs Account Management) mean neither pulls its weight; consolidate.

3. Convention consistency over convention choice. live_docs is not opinionated about WHICH naming convention; it encourages whatever convention is in use to be applied consistently. Gardening normalizes toward internal consistency (casing, separators, plurality), not a prescribed style.

4. Domains emerge from use, not from a seed. Ships with zero domains; does not presume what domains a user's documented system will have — the documented subject determines them. Identified at tag time. The current 0-usage state is correct.

5. Tag-time reuse nudge backed by a domain registry. A new ldoc capability lists in-use domains (e.g. ldoc domains). When creating/placing a doc, the tagger applies any applicable domains but is nudged to reuse an existing one over inventing. Inventing allowed only when none fits. Parallels belongs_to originate-at-birth / refine-by-gardening.

6. Gardening's domain role reframed around curating the shared vocabulary: consolidate outlier/synonym domains; assign docs to existing domains; validate each claimed membership is accurate; enforce convention-consistency. No ≥2-scopes test.

7. Scope/domain overlap is expected and acceptable. Orthogonal in purpose but values may correlate (most viewer-scope docs sharing a ui domain). The redundancy is fine; not noise.

8. Keywords and domains must not overlap. If a candidate keyword is/matches an existing domain, it belongs as a domain tag. Domain = governed filterable facet; keyword = ungoverned search alias that is not a domain.

9. Over-eager tagging is the primary failure mode all domain governance exists to prevent. Under-tagging is the correct bias; do not invent/apply domains to fill a slot.
