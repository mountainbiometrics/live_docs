Conceptual reframing of the live_docs model (docs-first, code deferred):
1. Remove 'index' as a doc type. A doc serves as a navigational signpost by virtue of having descendants (incoming belongs_to edges); any type can play that role.
2. Introduce/redefine 'scope' as a string field declaring a topological zone/facet. A doc's effective scope is the UNION of scope values along its WHOLE belongs_to genealogy, including its own. Scope is DERIVED from topology, not materialized per-doc; moving a doc re-scopes it (correct, intended). Anchor docs (structural components) set scope; leaves inherit.
3. Make explicit belongs_to vs requires: belongs_to forms a hierarchical DAG that DEFINES SCOPE (you are scoped under your parent and its whole genealogy); requires expresses dependency WITHOUT joining the family tree / without inheriting scope. Effective scope is computed over belongs_to ONLY.
4. Re-type the former index docs: Root Index -> component, renamed 'The live_docs system', anchors root scope. Structural groupings -> component, each anchoring its own scope. Foundational Principles -> a requirement (determine type vs level).
5. Reframe summarize-descendants: applies to ANY doc with descendants; it is a VARIATION OF CASCADE-CHECKING (redefining a child can reframe the parent).
6. Consequence: viewer entry-points must be derived structurally (no type:index); orphan definition becomes hierarchy-based.
Constraints: domain field unchanged; docs-only pass; do not touch viewer/livedocs/skill code; commit nothing.
