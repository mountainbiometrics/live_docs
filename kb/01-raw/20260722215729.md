ldoc session close unconditionally tries to materialize a creation-history entry for every doc touched in the session, including docs with type: reference — but reference docs refuse all history writes (even a leading creation entry), so session close fails whenever a reference doc was created mid-session. This was hit for real on 2026-07-22 while seeding a new store (the panelists project KB at ~/projects/panelists/kb): the workaround was hand-deleting the reference doc's WAL line from the session file before retrying close. Note the apply-to-docs skill's own Step 1b recipe creates exactly this kind of reference doc mid-session, so the bug is on the happy path. Fix: session close should skip history materialization for reference-type docs (or handle their refusal gracefully).
