Follow-up gardening + concept-capture on the session-based review-tracking rework.

GOAL 1 — Get explicit on naming and structure. The former "episode" was a virtual concept; the rework actualizes it as a concrete "session," which deserves its own component. Introduce an explicit **Editing Session** component within the Review Subsystem: the session is the actualized unit of editing work — one owner opens it, every change is stamped to it, and closing it produces exactly one review summary. Re-scope the session decisions under this new component so the review subsystem is not too broad/spread out:
- "Session-Identified Review Episode" → re-parent under Editing Session; rename to session-explicit ("Explicit Session Identity" — an editing session is identified by an explicit generated id, not a timestamp window). The "session is the episode made explicit" framing moves up into the component doc.
- "Session-Stamped History" → re-parent under Editing Session (keeping its requires→History Is Changes lineage; it exists to serve sessions).
- "Edge-Based Review Classification" → re-parent under the Review Summary component (it governs how the review summary files changes), not directly under Review Subsystem.

GOAL 2 — Capture architectural decisions embedded in the mechanism that the first pass missed. The flagged one: session context propagates AMBIENTLY THROUGH THE SHELL via the LDOC_SESSION environment variable. The exact variable name is incidental, but the architectural choice is durable: the open session's id lives in the shell environment so that independent `ldoc` invocations — and subagents that inherit that environment — all attribute their changes to the same open session, without threading a session id explicitly through command arguments. Chosen over: passing the session id explicitly on every command, or persisting it in a state file. Also: a session's id is time-sortable yet collision-resistant; and closing a session is what mints its review summary.
