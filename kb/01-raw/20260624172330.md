The following are conceptual principles and constraints extracted from the user's prompts that motivated the garden redesign plan. These are the abstract/motivating layer — constraints, goals, and principles — not the implementation decisions themselves (those were already ingested). Please ingest whichever of these represent genuinely new or additive concepts not yet captured in the knowledge base.

1. Single responsibility means single ownership, not just single topic. A doc that is written about by many actors, or whose claim is spread thin across several docs with no single one fully owning it, has no real owner — and an unowned claim is not truly managed. If three different docs are each 'partly in charge' of a claim, none of them is really in charge. The inverse of decompose (splitting overloaded docs) is therefore not just deduplication — it is enforcing singular ownership, which sometimes means folding or merging when responsibility is too diffuse.

2. An overgrown branch is a structural smell even when every child is correctly placed. Being 'in the tree' is necessary but not sufficient for a well-structured knowledge base. A signpost that has 100 direct children is a navigability failure even if every one of those children is correctly classified. Tree placement correctness (individual doc level) and tree navigability (branch level) are two independent axes.

3. Agentic pipelines produce sporadic inconsistency; sampling-based QA is the right response. When documents are created by agentic processes where subagents handle different parts independently, the output will exhibit intermittent, non-deterministic inconsistency in formatting, naming, and structure. The correct QA response is sampling-based spot-checking — not deterministic full-scan validation and not manual review.

4. Natural-language dispatchers map intent to phases; users address the dispatcher, not sub-skills. When a family of sub-skills is organized under a dispatcher, the user-facing design should allow natural-language intent, not require the user to know or address internal sub-skill names. Sub-skills must not be user-invocable directly — the dispatcher is the only entry point and only owner of an episode.

5. Folding cruft into parents is a distinct move from merging duplicates. Merge: two docs assert the same claim → one survives. Fold: a thin/incidental doc can be absorbed into its parent without making the parent less singular. Folding is safe only when the fold does not make the parent violate single-responsibility.

6. Shared prose includes are for cross-skill shared text, not shared procedure. When two skills need to share a definition (policy, criteria, prose), the right mechanism is a shared prose fragment referenced verbatim — not a sub-skill, which is for shared procedure. This distinction prevents over-engineering the skill graph.

7. Goal: skills that emit docs should check for an existing group/home, not defer entirely to gardening. A doc-emitting skill already holds the concepts and edges needed to pick the nearest coherent signpost at creation time. 'That is a gardening concern' should mean 'gardening will refine this,' not 'gardening will originate every placement.'
