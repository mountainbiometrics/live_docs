# Session digest — Cursor plugin packaging and multi-harness install (2026-07-21)

## What was built

1. Added `.cursor-plugin/plugin.json` so Cursor can load the live_docs skills plugin (Claude already had `.claude-plugin/`).
2. Pointed that manifest's `skills` at the existing shared tree `.claude/skills/` — no skill duplication.
3. Extended `install.sh` so `--plugin` installs into Claude Code (marketplace, when `claude` is on PATH) *and* Cursor (symlink into `~/.cursor/plugins/local/live-docs` when `~/.cursor` exists).
4. Light updates to `docs/install.md` and README so they describe both harnesses rather than Claude-only.

## What was decided (and why)

### Shared skills; harness-specific manifests only
Cursor and Claude Code each require their own plugin manifest format and identifier rules (Cursor rejects underscores; Claude's plugin id is `live_docs`). The durable choice: keep **one** skills tree and give each harness a thin adapter manifest that points at it. Duplicating skills per harness would drift; the skill content is the product, the manifests are incidental packaging.

### Installer installs into present harnesses via each harness's native mechanism
Shipping a Cursor manifest without installing it leaves Cursor users broken while Claude users work — that silently couples distribution to one harness. `install.sh` therefore discovers which harnesses are present and uses each one's documented install path (Claude CLI marketplace; Cursor has no plugin CLI, so the official local symlink under `~/.cursor/plugins/local/`). Skip a harness when its presence marker is absent; do not invent a Cursor home if Cursor was never opened.

### Multi-harness packaging is distribution, not harness coupling
Harness-agnosticism says live_docs does not own or require a particular agent harness. Optional packaging adapters for multiple harnesses *serve* that constraint: agents reach the same skills wherever they run. Requiring Claude-only install would have been the coupling.
