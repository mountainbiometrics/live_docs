Durable WHY-level insights from the skills-refinement session (dogfood post-mortem ldoc_refinements.md). Operational verbs (EXCAVATE, garden-cruft, garden-densify, verdict vocabulary) are HOW and live in skill prose, NOT the KB.

1. DETECTION IS THE SUPERSESSION GAP, NOT PROPAGATION. When a system-changing intent lands, the hard part is finding the docs it makes stale. Lexical/keyword search systematically misses them: a stale doc whose text predates the new vocabulary is never retrieved by a query phrased in the new terms. Remedy: reason over the whole topological cluster (belongs_to/scope neighborhood), not lexical overlap. Corollary: "zero docs superseded by a system-changing initiative" is a red flag (a likely detection miss), not a conservative win.

2. SKILLS MUST BE SELF-CONTAINED FOR EXTERNAL CALLERS. Agent-facing skill prose must not reference the internal KB (by doc id or doc title): skills ship to consumer repos that do not have this store's KB, so such references dangle. State the idea inline instead. Refines the existing constraint that agent-facing policy lives in skills/CLI not the KB.

3. PROVENANCE GROUPING IS NOT STRUCTURE. A signpost that groups docs by where they came from (same ingest/source) rather than by what part of the system they describe is an ingest artifact, not a real structural node. Corollary of belongs_to = the system's mental model.

4. EXCAVATION OVER DEPRECATION for stale-implementation docs (keep the why, strip the dead what; status was never wrong) — an application of capture-why + docs-as-code + delete-when-redundant, not a new principle.

5. STATUS BY INTENT, NOT CODE-CORROBORATION (plan-of-work → target; in-force-design → living) — an application of docs-lead-code-aligns, not a new principle.
