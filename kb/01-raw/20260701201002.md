Rework the live_docs review-tracking process to be session-based rather than purely timestamp-based.

Core design decisions (settled):
- A "session" is the existing "episode" concept made explicit via a generated session id — NOT a new conceptual layer. An episode/session spans one owner-skill's START→review window; today it is keyed by a START timestamp and reconstructed by scanning history entries with `at >= since`. The rework keys it by an explicit id instead.
- `ldoc session start` generates a session id (time-sortable + collision-resistant) and it is exported as the LDOC_SESSION env var; owner skills call this at their START step in place of capturing a `date -u` timestamp.
- History entries gain an additive `session` field alongside the existing `at` timestamp. Fully back-compatible: pre-existing history entries simply lack `session`. No migration of existing docs or reviews required.
- The `--note` flag on mutating commands (set/link/unlink) stamps the session id read from LDOC_SESSION onto the history entry it writes.
- `ldoc review new --session <id>` builds a review by selecting history entries tagged with that session id, twinning the existing `--since` timestamp path. The `--since` path is KEPT as a fallback — the two selectors coexist rather than one replacing the other.
- `ldoc session end --summary "..."` finalizes a session with a human summary, which becomes the review's summary and feeds richer review-summary counts in the viewer.
- Review-body edge classification default: changes that only touch `relates`/`provenance` edges are classified under "Minor Alterations"; changes touching `requires`/`belongs_to` (cascade-hard) edges are classified under "Revisions".
- Enforcement stance: warn-not-block initially (surface skipped/hand-written reviews as warnings, tighten to hard enforcement later).
- Rationale (the durable "why"): explicit session ids make episode membership exact, eliminating the misclassification that timestamp-window scanning suffers under overlapping episodes or clock skew. The review process is the primary human-in-the-loop mechanism for the store, and making it session-tracked + mechanical is a precondition for letting agents churn the KB with less supervision.
