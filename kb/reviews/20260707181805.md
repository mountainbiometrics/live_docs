## Additions
- [[20260707005433]]
  Comparison of live_docs to neighboring agent-doc tools (a code->docs generator, a rule enforcer, retrieval/MCP bolt-ons). Reinforces existing principles and surfaces two additions: surgical regeneration as the cascade repair action, and currency-not-retrieval as the system's substrate/scope boundary.
- [[20260707005515]]
  A living doc is kept current by being regenerated, not flagged or patched around: when a dependency moves, cascade rewrites each stale dependent to current truth from the graph — surgically, only the affected atomic node. Atomicity makes the local rewrite safe; the doc stays living, re-derived rather than snapshotted.
- [[20260707005524]]
  live_docs holds the intent behind a system — its decisions, rationale, constraints, and goals — and its job is keeping that knowledge accurate as reality changes: a write-time concern. Retrieving or serving the knowledge is a separate, read-time layer over a store that is already true; keeping it true, not access to it, is what the system owns.
- [[20260707164524]]
  Coding-agent harnesses and the retrieval layers around them (RAG, MCP, prompt-assembly) are heterogeneous, fast-moving, and not ours to own; live_docs couples to none of them. They are downstream, swappable layers that read the store. Being unopinionated about the harness follows from the system's job — keeping the knowledge true — and is a consequence of that boundary, not a gap.
- [[20260707164539]]
  live_docs points the arrow docs->code: the docs state the intended paradigm and the code aligns to them — the inverse of deriving docs from code. A doc/code mismatch becomes meaningful signal, so 'is the code aligned with the docs?' stays a real question — and a doc need not be implemented to be current.
- [[20260707170659]]
  Enforcing a decision is the easy half; evolving it as reality changes is the hard half. A decision is safely revisable only when its why (rationale, alternatives) and its dependencies are recorded — a context-free rule is enforceable but not revisable. That is what makes this a living decision-graph, not a static rulebook.
