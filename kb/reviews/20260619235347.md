apply-to-docs: conceptual reframing of the live_docs model (docs-first; code deferred). Retired the 'index' doc type — the navigational-signpost role is now structural (any descendant-bearing doc). Redefined 'scope' as a topology-derived facet whose effective value is the union along the belongs_to genealogy, anchored by structural components and inherited by subtrees. Made the belongs_to (defines scope/lineage) vs requires (dependency without scope) distinction first-class. Re-typed the 9 former index docs (root -> 'The live_docs system' component; 7 structural groupings -> components; Foundational Principles -> requirement). Generalized summarize-descendants as a cascade-check variation. Recorded the viewer entry-point / orphan redefinition consequence for the deferred code phase. domain field untouched.

## Additions
- [[20260619234841]]
- [[20260619234959]]
  A doc is not a navigational signpost by declaring type:index — it serves that role by virtue of having descendants (incoming belongs_to edges). Any type (component, requirement, principle, decision, ...) can have descendants and play the signpost role. 'index' is therefore removed from the type taxonomy; the role is read off topology, not off a type value.
- [[20260619235018]]
  scope is a string field naming a topological zone. Set on a doc, its value applies to that doc and its whole belongs_to subtree; effective scope is the union along the full belongs_to genealogy, including its own. Anchors (structural components) set it; most docs inherit. Derived from topology, not materialized — moving a doc re-scopes it.
- [[20260619235034]]
  belongs_to forms a hierarchical DAG that defines scope: belonging to a parent scopes you under it and its whole genealogy. requires expresses dependency without joining that family tree — no scope/lineage inheritance. Effective scope is computed over belongs_to only, never requires.
- [[20260619235049]]
  With the index type retired, viewer entry points must be derived structurally — roots of large subtrees (no belongs_to, many descendants) and scope-anchoring components — not from type:index. The orphan definition likewise becomes hierarchy-based: a doc with no belongs_to that is not a legitimate top-level component is an orphan.
