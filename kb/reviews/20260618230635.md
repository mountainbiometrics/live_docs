## Additions
- [[20260618230214]]
  The six bedrock principles every other live_docs decision derives from: drift is the enemy (Living over Stale), made checkable by Dependency Tracking and Single Responsibility. The frame around them — stay tool-agnostic, manage cognitive load, automate over human diligence. Read these first; the requires-graph fans out from here.
- [[20260618230215]]
  How docs connect: a typed-edge graph with four kinds — belongs_to, requires, relates, provenance — each named for behavior, not category. Acyclicity is enforced per edge type, so cycles are legal where they make sense. Start at the vocabulary doc; the naming principle explains the rest.
- [[20260618230216]]
  The lifecycle and schema of one doc. A unified status field replaces the old state/status split, and a derived is_living axis decides what cascade-check may rewrite. Deprecation demands a superseded_by edge and Correction section, never a bare flip. The rest are field rules. Start at the status enum.
- [[20260618230223]]
  The post-hoc review subsystem. Official docs must be reviewable, but review never gates a change — it runs after the fact on a queue kept orthogonal to the docs. Reviewers read a synthesized change summary, not diffs. Signoffs are multi-party with no auto-bless. Start at the reviewable goal.
- [[20260618230224]]
  How knowledge enters the store. An async inbox decouples capture from a batch ingest pass. Above it sit the workflows that materialize intent: plan docs-first, apply-to-docs (which pauses on a large blast radius), and reconcile for already-made changes. The governing rule throughout: understand-before-write.
- [[20260618230225]]
  The ldoc porcelain — the system's single access layer. The KB is treated as a database reached only through this API, so mutators stay dumb and skills supply judgment. The component doc is the entry point; supporting decisions cover the three descriptors (label/title/summary), batch/multi-ref input, typed wiki-link rendering of references, the imported-timestamp for reference docs, and the forward capability roadmap.
- [[20260618230226]]
  How the store is laid out. Content lives in numbered boxes under kb/ by distillation stage, with paths in config so skills stay path-agnostic. Docs use opaque timestamp IDs with titles in frontmatter. Grouping fields domain and scope are flat; the root index is a deliberate stub.
