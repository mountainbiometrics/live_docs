## Context

Docs need stable identifiers for cross-referencing. Human-readable filenames (slugs) seem ergonomic but break when titles change, creating dead links. Numeric IDs are stable but opaque.

## Decision

Filenames are opaque timestamp-derived IDs (e.g. `20260615100000.md`). The human-readable title lives only in frontmatter. Structure and navigation live in indexes and tooling, not in filenames.

## Consequences

IDs are permanently stable regardless of title changes (P1: no tool required to manage renames). This is the Zettelkasten/Kiste pattern: notes are nameless in the box; structure is imposed by the tooling layer (P5). The cost is that the filename alone is not meaningful — a lookup or index is required to find a doc by topic. This tradeoff is acceptable because the index is a generated artifact that any tool can rebuild.
