## Context

The markdown files are the storage engine, but agents kept hand-rolling JSON parsing and cat loops and referring to docs by opaque ids. The raw plumbing was being re-implemented in every skill and every agent turn.

## Decision

Provide a unified porcelain over the plumbing: a `ld` CLI plus an importable `KB` class giving label-resolving reads (`get`/`show`/`find`/`neighbors`/`graph` that return bodies and edges-as-labels, never bare filenames) and dumb mutation primitives (`new`/`set`/`link`/`unlink`/`history`/`ingest-raw`). Mutators carry NO judgment; the skills (`revise-doc`, `ingest-reference`, `cascade-check`) decide when to add history, cascade, or dedup. The files-on-disk core stays for git/tool-agnosticism; the porcelain is optional convenience.

## Consequences

- Refines the logic-in-scripts decision; skills express steps as `ld` verbs instead of throwaway plumbing.
- The KB is queryable like a database while remaining plain markdown on disk.
- Agents stop needing to know file paths or id formats; resolution accepts id, slug, or title substring.
