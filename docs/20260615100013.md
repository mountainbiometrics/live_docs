## Context

Reference material comes in several flavors: brainstorm notes, plans, clippings, external links. These could each become a top-level `type` value, but that risks taxonomy bloat as new flavors emerge.

## Decision

Subtypes of reference material are expressed as a `kind` field on `type: reference` docs (e.g. `kind: brainstorm`, `kind: clipping`). No new top-level types are added for these.

## Consequences

The top-level type taxonomy stays small and stable (P4: each type has one reason to exist; P5: the taxonomy is easy to hold in working memory). New reference flavors can be added by assigning a `kind` value without any schema change. The risk is that `kind` values proliferate unchecked; a controlled vocabulary for `kind` can be defined in a type-definition doc without touching the type taxonomy itself.
