## Statement

A doc should have exactly one reason to change. Docs are designed like well-factored code: clear boundaries, minimal surface, composable building blocks.

## Rationale

The test is: "can this doc change for more than one reason?" If yes, split it. A cascade check firing should mean multiple genuine single-responsibility units changed together — that is normal and expected. A wide cascade triggered by a routine edit is a design smell: the changed doc was carrying multiple responsibilities. This is the foundational principle; all structural decisions derive from it.
