## Context

Change provenance is important for understanding why a doc is in its current state. Git commit history is the natural place to store this, but it requires git to be present and used.

## Decision

Each doc carries a `history` list in its frontmatter: timestamped entries with a plain-language summary of what changed and why. Git is optional layering on top.

## Consequences

Provenance is visible to any reader without any tooling (P1). Summaries are human-authored, so they explain intent — something git diffs do not (P2). The cost is that history must be updated manually or by the agent making the change; it will not self-populate from file system mutations. A gardening skill can detect docs with stale or missing history entries.
