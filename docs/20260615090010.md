## Purpose

An `index` doc is a generated map of a domain or slice of the system. It is a navigation aid, not an authority — its `## Children` section is produced by the `reindex` skill and should never be hand-edited.

## Required Fields

All canonical baseline fields. No type-specific additions.

## Lifecycle

Always `living`. An index is never `historical` — if a domain is retired, its index is removed (or emptied), not archived.

## Cascade Behavior

Index docs are outputs, not inputs — they do not drive cascades. When other docs change, the `reindex` skill regenerates the relevant index. An index should never appear in another doc's `depends_on`.

The presence of a cascade originating from an index doc is always a design error: either the index is being treated as an authority it is not, or something was hand-edited in the `## Children` section.
