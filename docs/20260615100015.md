## Context

The system has a type taxonomy (principle, decision, reference, etc.). These types need to be defined somewhere. An external schema file or README would work but would exist outside the doc graph.

## Decision

Each type is defined by a doc of `type: type` living in the corpus itself. The system documents its own structure using its own structure.

## Consequences

The system is self-contained and self-describing (P1: no external schema required; P6: the type definitions can be maintained with the same skills as any other doc). This is the Tolaria pattern applied to live_docs. A reader who wants to understand what a `principle` is can find the answer inside the system, not in a separate README. Type docs participate in the same cascade and dependency machinery as all other docs, so changes to a type definition trigger cascade checks on all docs of that type.
