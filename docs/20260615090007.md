## Purpose

A `guide` doc gives step-by-step or pattern-based instructions for doing something in the system. It is the operational layer: where decisions and principles meet day-to-day practice.

## Required Fields

All canonical baseline fields. No type-specific additions.

## Lifecycle

`living` while the instructions remain accurate. Update in place (with a `history` entry) for routine improvements. Set `historical` only when the workflow being described no longer exists.

## Cascade Behavior

When a guide changes, `cascade-check` should examine:
- `use-case` docs the guide implements — does the guide still faithfully describe the flow?
- `component` docs referenced in the guide's steps — do their interfaces still match?

Guides should cascade inward (toward what they describe), not outward. A guide that triggers wide cascades was probably describing too broad a workflow; split by task.
