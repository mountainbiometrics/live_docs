## Purpose

A `type` doc defines one document type in the live_docs taxonomy. It exists so the system can describe its own vocabulary in the same format it uses for everything else.

## Required Fields

All canonical baseline fields. No type-specific additions.

## Lifecycle

`living` as long as the type is in active use. Set to `historical` only if the type is retired and replaced by another — never deleted, so old docs of that type remain interpretable.

## Cascade Behavior

Changes to a `type` doc should prompt `cascade-check` to examine:
- All docs of the changed type (their shape may now be invalid or misaligned).
- Any `index` docs that reference docs of this type.

Cascade scope is intentionally bounded: a type doc owns the definition of a vocabulary term, not the content of every doc using it. A wide cascade here signals the type was doing double duty and should be split.
