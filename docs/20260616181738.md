## Decision

The review queue is **orthogonal** to the docs themselves. A changeset *references* the docs it touched — forward links, exactly like a commit lists the files it changed. Docs carry **no** pending-review state: nothing on a doc gates on whether a changeset that touched it has been reviewed.

The query "which changesets touched this doc?" is a **generated reverse view**, computed from the changesets' forward links — precisely the way `dependents` is generated from `depends_on`.

## Rationale

- **Orthogonality follows from post-hoc review** (review-is-post-hoc): if review never gates, a doc has no reason to carry a `pending_review` flag. Keeping review state off the doc avoids polluting the doc with a second, unrelated lifecycle.
- **Single-responsibility** (single-responsibility): a doc's frontmatter is responsible for *what the doc asserts and depends on*, not for the audit lifecycle of every changeset that grazed it. The changeset owns its own state.
- **Unidirectional edges** (unidirectional-deps): forward links are authored once on the changeset; the "touched-by" view is derived, never hand-maintained. This reuses the existing reverse-index machinery rather than inventing a new bidirectional link type.

## Consequence

Adding or reviewing changesets never mutates the docs they reference. The doc store and the review ledger evolve independently, joined only by generated reverse views.
