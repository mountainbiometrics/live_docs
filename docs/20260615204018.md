## Context

idea_dump explicitly called out: 'For reference docs we'd want to know their original creation timestamp, as well as when we added it to our docs.' A standard doc's `created:` field records when the doc was written in live_docs. For reference material, the source content may predate the import significantly (e.g. a blog post from 2022 ingested in 2026). Conflating these two timestamps loses the original provenance information.

## Decision

`type: reference` docs carry an `imported:` field (ISO 8601 datetime) in frontmatter, recording when the material was added to live_docs. The `created:` field records when the live_docs doc was created (which equals the import time). The `source:` field records the original origin (URL, person, filename, date). Together these three fields reconstruct: what it is (`source:`), when the original existed (`source:` details), and when we captured it (`created:` / `imported:`).

## Consequences

- `imported:` is a reference-type-specific required field, already specified by the reference type doc (090009) but without the rationale for why it exists alongside `created:`.
- For the raw tier (`raw/<id>.md`), the file itself is the import; no separate `imported:` field is needed there since raw docs are not graph nodes.
- For normalized reference docs in `docs/`, both fields should be populated by `new_doc.py` at creation time.
