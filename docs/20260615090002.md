## Purpose

A `goal` doc names a desired outcome — something we want to be true about the system or organisation that isn't yet fully true. Goals motivate decisions and requirements; they are the "why" above the "what".

## Required Fields

All canonical baseline fields. `state: target` is typical (a goal describes where we want to be). `state: actual` is valid if documenting a goal that has been achieved and is worth preserving as context.

## Lifecycle

`living` while the outcome is still being pursued. `historical` once met (with a history entry recording closure) or abandoned (with a history entry explaining why).

## Cascade Behavior

When a goal changes, `cascade-check` should examine:
- `decision` docs that depend on this goal — do they still serve it?
- `requirement` and `use-case` docs in `depends_on` chains from this goal.

Keep the cascade narrow: goal changes should be rare and intentional. A goal that cascades widely on a routine update was probably carrying implementation detail it should have delegated to a decision or requirement.
