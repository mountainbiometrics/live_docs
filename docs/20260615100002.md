## Statement

Systems and code have dependencies; documentation must convey and enforce that same complexity. Every doc tracks what influences it, and changes are checked against the dependency graph.

## Rationale

Undocumented dependencies are invisible drift vectors. When doc A changes because it depends on doc B, and that relationship is not recorded, B can be updated without anyone knowing A is now stale. Making dependencies explicit turns an invisible problem into a checkable one.
