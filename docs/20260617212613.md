## Context

The frontmatter schema has several list-valued fields: `requires`, `belongs_to`, `relates`, `provenance`, `superseded_by`, `history`, and the `tags` sub-object (`domain`, `scope`). When a doc has no edges of a given type, two representations are possible: write the field as `[]` (explicit empty) or omit the field entirely. Early docs used `[]` uniformly, producing noisy frontmatter where most of the content was empty placeholders.

## Decision

Empty list fields are omitted from frontmatter. Absent means empty/default, and absent is valid. Scalar fields (`type`, `status`, `level`, `id`, `title`, `label`, `created`) are always written explicitly. The `tags` block is omitted entirely when both `domain` and `scope` are empty.

## Consequences

- New docs created by `ldoc new` omit any edge list that would be empty.
- The canonical frontmatter form is minimal: only fields with actual content appear.
- Validate does not error on absent list fields; it treats them as empty.
- Migrating existing docs that have `[]` entries is a cosmetic bulk pass; it carries no semantic change.
