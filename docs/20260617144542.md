## Statement

Edge types should be named after what they *do* in the system — their cascade behavior, removal jeopardy semantics, acyclicity constraint, and validate rules — not after what they *feel like* conceptually (hierarchical, associative, dependency-like).

## Method

1. Enumerate all functional dimensions an edge can have (forward cascade, reverse cascade, removal jeopardy, structural membership, acyclicity, target-outside-graph legality, lifecycle side-effects).
2. For each candidate type, fill in the matrix row.
3. Collapse rows with identical profiles — they are the same type.
4. Name the surviving types after the behavior that makes each row unique.

## Why

Naming from conceptual feel reproduces the exact failure mode that created the DAG/web confusion: 'dependency' connoted build-order, silently made the graph acyclic, and the intended influence-web got skipped. A name like 'belongs_to' is chosen because it specifically implies orphan semantics (its primary behavioral distinguisher), not because it sounds hierarchical.
