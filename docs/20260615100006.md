## Context

Cascade checks need to run when a doc changes. The obvious integration points are git hooks or CI pipelines, but both require specific tooling to be configured and present.

## Decision

Cascade checks are implemented as a `cascade-check` skill invoked on demand by an agent, not wired into git hooks or CI.

## Consequences

The system remains tool-agnostic (P1): it works identically with or without git. Checks are not automatic on commit, but that is acceptable — the skill can be called by any agent or human workflow that knows a doc changed. The tradeoff is that a user who never invokes the skill can accumulate silent drift; this is addressed by gardening pass skills (P6).
