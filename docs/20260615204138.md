## Context

idea_dump proposed index/signpost docs as navigation aids and explicitly described 'skills for grouping docs under a new index/folder (w/ summary)' and 'including aggregated summaries of all descendants.' The concern was that traversing a flat, highly-atomic doc store requires either loading many docs into context or having summary rollups at the index level to narrow the search before descending.

## Decision

Index docs carry aggregated content summaries of their descendants. These summaries make index docs true navigational signposts: a reader can understand what's in a subtree without opening each child doc.

## Consequences

- A `summarize-descendants` skill produces and updates these summaries.
- Summaries are cascade-sensitive: when a descendant doc changes, the ancestor index summary is stale. `cascade-check` propagates the stale signal upward through `belongs_to` edges.
- The cognitive-load principle (100004) grounds this: summaries let a reader navigate by scanning, not by absorbing every doc in a branch.
