## Context

idea_dump proposed index/signpost docs as navigation aids and explicitly described 'skills for grouping docs under a new index/folder (w/ summary)' and 'including aggregated summaries of all descendants.' The concern was that traversing a flat, highly-atomic doc store requires either loading many docs into context or having summary rollups at the index level to narrow the search before descending.

## Decision

In v1, index docs contain a generated `## Children` table (id, title, type, status) but do not include aggregated content summaries of descendants. The table is sufficient for navigation in the current small corpus. Descendant summary rollups are deferred: they add significant complexity (each child's body must be summarized and stored, and those summaries must be regenerated on child changes) for unclear benefit at the current corpus size.

## Consequences

- `reindex` produces a table, not prose summaries. The reindex skill and existing index docs are correctly aligned with this decision.
- When the corpus grows large enough that the children table is no longer sufficient for navigation, this decision should be revisited and a summarize-descendants skill introduced.
- The cognitive-load principle (100004) motivates the eventual need for summaries; this decision records the conscious deferral.
